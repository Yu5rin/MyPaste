# アタイの貼り付け

Excel 使用時に **`Ctrl+B` を `Ctrl+Shift+V`（値貼り付け）にリマップ**する、Windows 常駐アプリです。
キーの組み合わせと対象アプリは、[設定画面](#設定画面) で変えられます。
さらに、[キー割り当て](#キー割り当て) で「このキーを押したら、この動作」を自由に追加できます
（キーを送る・定型文を入力する・プログラムを開く・書式なしで貼り付け・文字を整えて貼り付け・
クリップボードの履歴から貼り付け・ウィンドウを常に手前に表示 など）。
Rust 製・単体 EXE（ポータブル）で、通常ユーザー権限で動作します。

> **ダウンロード**: ビルド済みの `Atai-paste.exe` は
> [Releases](https://github.com/Yu5rin/MyPaste/releases) から入手できます。
> 導入と更新の手順は [インストール](#インストール) を参照してください。

## 概要

| 項目 | 内容 |
| --- | --- |
| 目的 | Excel 使用時に `Ctrl+B` → `Ctrl+Shift+V` を送出する（キーは設定画面で変更可） |
| 範囲 | フォアグラウンドが Excel（`EXCEL.EXE`）のときのみ有効（対象アプリは設定画面で追加可） |
| 動作環境 | Windows 10 / 11（64bit）。**Excel は Microsoft 365 バージョン 2308（2023年8月）以降が必須**（下記参照） |
| 配布形式 | 単体 EXE（ポータブル） |
| 権限 | 通常ユーザー（権限昇格不要） |

> **重要: Excel のバージョン要件**
> `Ctrl+Shift+V`（値貼り付け）のショートカットは、**Microsoft 365 のバージョン 2308（2023年8月）以降**で
> 追加されたものです。**Excel 2019 / 2021（永続版）や、それより古い Microsoft 365 では割り当てられていません。**
>
> 対応していない Excel でこのアプリを ON にすると、`Ctrl+B` は握りつぶされて `Ctrl+Shift+V` が
> 送出されるものの Excel 側がこれを認識しないため、**太字にする（`Ctrl+B`）ことも値貼り付け（`Ctrl+Shift+V`）
> することもできなくなります**。「`Ctrl+B` が壊れた」ように見えますが、原因はこのアプリによる
> リマップです。該当する Excel をお使いの場合は、トレイメニューでこのアプリを OFF にするか終了してください。

## 機能

- **値貼り付け**: 対象アプリ（既定は Excel）が最前面のとき、`Ctrl+B` を押すと `Ctrl+Shift+V`（値貼り付け）を
  送ります。押しっぱなしにしても最初の 1 回だけ送ります。キーと対象アプリは変えられます
  （[設定画面](#設定画面)）。対象アプリ以外では、キーはそのまま通します。
- **キー割り当て**: 好きなキーの組み合わせに動作を割り当てられます（AutoHotkey や PowerToys の
  キーボードマネージャーのような使い方）。動作は「キーを送る」「文字を入力する」「プログラムやファイル・
  URL を開く」「書式なしで貼り付け」「文字を整えて貼り付け」「定型文を貼り付け」「クリップボードの履歴から
  貼り付け」「前面のウィンドウを常に手前に表示」「キー割り当ての一覧を表示」「何もしない（キーを無効にする）」の
  10 種類。アプリごとに効かせることもできます。詳細は [キー割り当て](#キー割り当て) を参照してください。
- **クリップボードの履歴と定型文**: コピーした文字や画像（スクリーンショットなど）を覚えておき、`Ctrl` の 2 回押しやキーの組み合わせで
  一覧を出して貼り付けられます。終了しても暗号化して残せます。よく使う文は定型文として登録できます。
  詳細は [クリップボードの履歴](#クリップボードの履歴)・[定型文](#定型文) を参照してください。
- **入力モードの表示**: IME の入力モード（`あ` / `A` / `カ` / `ｶ` / `Ａ`）を切り替えた瞬間に、画面に
  大きく表示し、すぐ消します。いまのモードを、入力位置やマウスカーソルの横に小さな印で
  出し続けることもできます。詳細は [入力モードの表示](#入力モードの表示) を参照してください。
- **トレイメニュー**: タスクトレイのアイコンをクリックすると、機能の ON/OFF（チェックマーク）と、設定などの
  画面を開く項目が出ます（[使い方](#使い方)）。ON/OFF の状態は保存され、次の起動でも同じになります。
  アイコンは、値貼り付けが ON のとき黒「B」、OFF のとき赤い禁止マーク付きになります。
- **設定の引っ越し**: 設定・キー割り当て・定型文を 1 つのファイルに書き出し、新しい PC で読み込めます
  （[設定の引っ越し](#設定の引っ越し)）。
- **更新の確認と適用**: 起動したときと、起動している間の 6 時間おきに GitHub の最新リリースを調べ、
  新しいバージョンがあれば入れ替えます。詳細は [自動更新](#自動更新) を参照してください。
- **二重起動の防止**: すでに起動しているときにもう一度起動しても、何も表示せずに終わります
  （起動しているものはトレイにあります）。
- **ログ（トラブル調査用）**: 設定画面で ON にすると、`log.txt` に動作のログを残します（既定は OFF）。
  詳細は [ログ](#ログトラブル調査用) を参照してください。

## インストール

1. [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) から `Atai-paste.exe` をダウンロードします。
2. 任意のフォルダに置き、ダブルクリックで起動します。インストーラーは無く、管理者権限も要りません。

`Program Files` 配下など書き込めない場所に置くと、自動更新は行われず、新しいバージョンが見つかったときに
手動での入れ替えを案内します（[自動更新](#自動更新) を参照）。設定や記録は `%LOCALAPPDATA%\Atai-paste` に
置くため、引っ越しのときはそのフォルダを写すか、設定画面の「設定を書き出す...」を使ってください。

### 設定や記録を置く場所

設定・キー割り当て・定型文（`settings.json`）、クリップボードの履歴（`clip_history.dat` と、画像を置く `clip_images` フォルダ）、
動作の記録（`log.txt`）、更新の確認時刻（`update_state.json`）は、**実行ファイルの下の `data` フォルダ**に
置きます（初めて起動したときに作ります）。

```
任意のフォルダ\
 ├ Atai-paste.exe
 └ data\
    ├ settings.json
    ├ clip_history.dat
    ├ update_state.json
    └ log.txt
```

- PC を引っ越すときは、`Atai-paste.exe` と `data` フォルダをまとめて新しい PC へ写せば、そのまま使えます
  （設定画面の「設定を書き出す...」でも引っ越せます）。ただし `clip_history.dat` は Windows の機能（DPAPI）で
  暗号化しているため、**別の PC・別のユーザーでは読めず、空の履歴から始まります**。
- 以前の版（実行ファイルと同じフォルダに置いていた版）から上げたときは、最初の起動で
  これらのファイルを `data` フォルダへ移します（`data` フォルダに同じ名前のファイルがあれば、そちらを使います）。
- `Program Files` 配下など書き込めない場所に置いた場合は、`%LOCALAPPDATA%\Atai-paste` に置きます。

> **SmartScreen の警告について**: 実行ファイルはコード署名していないため、初回起動時に
> Windows SmartScreen の警告が出る場合があります。「詳細情報」→「実行」で起動できます。

### 更新方法

- **アプリ内で更新する**: 起動したときと、起動している間の 6 時間おきに新しいバージョンを確かめます。
  見つかったときの動きは、設定画面の「新しいバージョンが見つかったら」で選べます（既定は「尋ねてから更新する」）。
  トレイメニューの「更新を確認」からも、いつでも更新できます。仕組みは [自動更新](#自動更新) を
  参照してください。
- **手動で更新する**: トレイメニューの「終了」でアプリを終了してから、
  [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) の新しい `Atai-paste.exe` で
  元のファイルを上書きします。同じ場所に置けば、自動起動の設定もそのまま使えます。

更新後もアイコンが以前のまま表示される場合は、Windows のアイコンキャッシュが原因です。
`ie4uinit.exe -show` を実行するか、サインインし直してください。

## 使い方

1. `Atai-paste.exe` を任意のフォルダに置いて起動します（インストール不要）。
2. タスクトレイに「B」アイコンが表示されます。
3. Excel を最前面にして `Ctrl+B` を押すと、`Ctrl+Shift+V`（値貼り付け）が送られます。
4. そのほかの操作は、トレイのアイコンをクリック（左でも右でも）して出るメニューから行います。

```
アタイの貼り付け vX.Y.Z        ← 今のバージョン（選べません）
──────────────
✓ 値貼り付け（Ctrl+B）         ← 機能の ON/OFF。チェックが付いているものが ON
✓ キー割り当て
✓ クリップボードの履歴
✓ 入力モードの表示
──────────────
設定...                        ← 画面を開く
キー割り当ての編集...
定型文の編集...
キー割り当ての一覧
──────────────
✓ Windows の起動時に実行       ← スタートアップフォルダにショートカットを作る・消す
更新を確認
使い方を開く                   ← このページをブラウザで開く
──────────────
終了
```

- 機能の ON/OFF は `settings.json` に保存され、次の起動でも同じ状態になります。
- 「値貼り付け」を OFF にすると、アイコンが赤い禁止マーク付きになります。
- 「クリップボードの履歴」を OFF にしても、保存してある履歴は消えません（ON に戻すと、また使えます）。
- メニューの項目は、かっこの中の文字のキー（例: 設定は `S`）でも選べます。

## 設定画面

トレイメニューの「設定...」で開きます。4 つのタブに分かれています。「OK」を押すと `settings.json` に
書き込んで閉じ、**その場で反映**します（アプリの再起動は要りません）。「適用」は、閉じずに保存します。
保存していない変更があるまま「キャンセル」や `Esc` で閉じようとすると、確かめるメッセージが出ます。

| タブ | 内容 |
| --- | --- |
| 全般 | Windows の起動時に自動で実行する、起動時に新しいバージョンを確認する、起動している間も 6 時間おきに確認する、新しいバージョンが見つかったら（尋ねてから更新する・尋ねずに更新する・知らせるだけ）、動作のログを保存する（「ログを開く」で `log.txt` を開けます）、設定の書き出し・読み込み、「設定フォルダーを開く」、「すべて既定値に戻す」 |
| 値貼り付け | 押すキー（`Ctrl` / `Shift` / `Alt` と、`A`〜`Z`・`0`〜`9`・`F1`〜`F12` の組み合わせ。既定は `Ctrl+B`）と、対象アプリ（プロセス名を 1 行に 1 つ。既定は `EXCEL.EXE`。「アプリを選ぶ...」で、開いているアプリから選んで足せます） |
| 入力モード | 表示の ON/OFF、切り替えたときに大きく表示するか、小さな印を出すか、出す場所（入力位置の横・マウスカーソルの横）・大きさ（12〜48 px）・出すとき（おまかせ・打ち始めたときだけ・出し続ける）・不透明度、表示する位置、配色（ダーク・ライト）、表示時間（0.1〜5 秒）、フェードアウトの時間（0〜2 秒）、大きさ（40〜600 px）、不透明度（30〜100 %）、全画面のアプリでは表示しない。時間は秒で入力し、`1.5` のような小数も使えます。「プレビュー」で試しに表示できます |
| クリップボードの履歴 | 履歴の ON/OFF、一覧を出す操作、一覧の見た目（出す位置・配色・幅・不透明度・1 ページの件数・貼り付けても出したままにするか）、残す件数、終了しても残すか、画像も残すか、履歴に残さないアプリ、「履歴をすべて削除」（[クリップボードの履歴](#クリップボードの履歴) を参照） |

- 入力に誤りがあるときは、その欄のあるタブに切り替えて知らせます。
- **設定フォルダーを開く**: `settings.json` を選んだ状態でエクスプローラーを開きます。
- **すべて既定値に戻す**: 確かめてから、すべてのタブの値を既定値にします（「OK」か「適用」を押すまでは
  保存しません）。キー割り当て・定型文・履歴は変わりません。
- **書き出す... / 読み込む...**: 下記の [設定の引っ越し](#設定の引っ越し) を参照してください。

### 設定の引っ越し

新しい PC へ移るときは、古い PC の設定画面の「全般」タブで「書き出す...」を押し、できたファイル
（既定の名前は `アタイの貼り付けの設定.json`）を新しい PC へ持っていきます。新しい PC では、
`Atai-paste.exe` を置いて起動し、同じ場所の「読み込む...」でそのファイルを選びます。

- 含まれるもの: 値貼り付けのキーと対象アプリ、入力モードの表示、クリップボードの履歴の設定、
  キー割り当てと定型文のすべて、ログ・更新確認の設定、自動起動の状態。`settings.json` に手で書いた項目も含みます。
- 含まれないもの: クリップボードの履歴の中身（暗号化しているため、ほかの PC では読めません）。
- 読み込むと、今の設定とキー割り当て・定型文を**置き換えて**、すぐに使い始めます（再起動は要りません）。
  読み込むファイルにキー割り当てや定型文が書かれていなければ（前の版で書き出したファイルなど）、
  今のものを残します。
- 更新の確認先（`update` の URL）は、読み込むファイルの値を使わず、今のままにします
  （受け取ったファイルで、別の配布元から更新させられないように）。
- 書き出すのは**保存済み**の設定です。画面で変えたばかりの値は、先に「適用」してから書き出してください。
- キー割り当てだけを移したり、今の割り当てに足したりするときは、キー割り当て画面の
  「書き出す...」「読み込む...」を使います。
- `Atai-paste.exe` と `data` フォルダをまとめて写す方法もあります（[設定や記録を置く場所](#設定や記録を置く場所)）。

### 設定ファイルを手で書き換えたとき

`settings.json` に書き間違いがあっても、読める部分はそのまま使います。読めなかった所は既定値で動き、
起動したときにどこが読めなかったかを知らせます。元の中身は `settings.json.bak` に写しておきます
（そのあと設定を保存すると、読めなかった所は既定値に置き換わるため）。

## クリップボードの履歴

コピーした文字や画像（スクリーンショットなど）を覚えておき、あとから一覧で選んで貼り付けられます
（Clibor や Ditto のような使い方です）。
トレイメニューの「クリップボードの履歴」にチェックを付けるか、設定画面の「クリップボードの履歴」タブで
「コピーした文字や画像を履歴に残し、一覧から選んで貼り付ける」を ON にすると使えます（既定は OFF）。

一覧を出す操作をすると、入力位置（またはマウス）の近くに、タイトルバーの無い、1 ピクセルの枠だけの
細長い半透明の画面が出ます（Clibor のメイン画面のような形です）。出す位置を変えると、画面の右端の
縦のパネルや、画面の下の横長の帯にもできます（[一覧の出し方](#一覧の出し方) を参照）。

```
┌─────────────────┐
│ 履歴 │ 定型文 │ 画像 │ 1〜20 / 1000 │ ← タブ（Tab・左右の矢印キーかクリックで切り替え）
│  1 見積書 2026年度 第…          │
│  2 東京都千代田区丸の内         │   ┌────────────┐
│  3 よろしくお願い…        3行  │ → │選んだものの全文    │
│  …                              │   │（1 行に収まらないとき）│
│ 20 …                            │   └────────────┘
└─────────────────┘
```

- **タブ**: 「履歴」（コピーした文字）・「定型文」（登録しておいた文）・「画像」（コピーした画像）。
  `Tab` / `Shift+Tab`・左右の矢印キーか、タブのクリックで切り替えます。履歴が空のときは、中身のある
  最初のタブから始まります。
- **一覧**: 1 ページに決めた件数（既定 20 件）。1 行に 1 件、番号・最初の行（定型文は名前）・行数
  （2 行以上のとき）を出し、1 行おきに色を変えています。
- **全文の吹き出し**: 選んでいるものが 1 行に収まらない（複数行か、途中で切れている）とき、定型文は
  いつも、選んだ行の横に全文を出します（長いものは 20 行まで）。
- **選び方**: マウスを乗せると選ばれ、クリックで貼り付けます。キーボードでは上下の矢印キーで選び、
  `Enter` で貼り付けます。`Home` / `End` でページの最初・最後へ、`Ctrl+Home` / `Ctrl+End` で全体の
  最初・最後へ移ります。
- **ページ**: `PageUp` / `PageDown`、マウスのホイールで前後のページへ移ります。
- **右クリックのメニュー**（またはアプリケーションキー・`Shift+F10`）: 貼り付け、ピン留めする・外す、
  定型文に登録（履歴のとき）、この履歴を削除、貼り付けても出したままにする、定型文の編集...、閉じる。
  行の無い所を右クリックしたときは、行に対する項目は選べません。
- **出したままにする**: 見出しの「出したまま」を押すか、`K` を押すと、貼り付けても一覧を閉じなく
  なります（続けていくつも貼り付けたいときに。もう一度押すと元に戻ります）。閉じるときは `Esc` です。
  設定画面でも切り替えられ、変えた値は次からも使います。
- **ピン留め**: 大事な履歴をピン留めすると、一覧のいちばん上にまとめて出し（左端に色の線が付きます）、
  残す件数や大きさの上限を超えても消えません。設定画面の「履歴をすべて削除」でも残ります（一覧の
  「この履歴を削除」では消せます）。履歴を選んで `P` を押しても切り替えられます。最大 1,000 件。
- **定型文に登録**: 履歴を定型文に登録します。すでに同じ本文がある・長すぎる（2 万文字を超える）・
  件数の上限のときは、画面に「登録済み」「長すぎ」「上限」と短く出ます。
- **貼り付けたものを上に移す**（既定は ON）: 一覧から貼り付けた履歴を、いちばん上（ピン留めの次）に
  移します。設定画面で OFF にできます。
- **半透明**: 不透明度は設定画面で決めます（既定 90%）。一覧の上で `Shift` を押しながらホイールを
  回しても変えられ（奥に回すと濃く、手前に回すと薄く）、変えた値は次からも使います。
- **配色**: 設定画面で「Windows の色」「ライト」「ダーク」「ブルー」「グリーン」から選べます
  （全文の吹き出しも同じ配色になります）。
- **閉じる**: `Esc`、ほかの場所のクリック、または一覧を出す操作（`Ctrl` の 2 回押しなど）を
  もう一度すると、何もせずに閉じます。
- **1 件を消す**: 履歴を選んで `Delete` を押すと、その 1 件を消します
  （間違えてコピーしたパスワードなどを消すときに）。
- 画面の幅（既定 260 ピクセル。200〜600）と 1 ページの件数（10〜40）は、設定画面で変えられます。

- **貼り付け方**: 選んだものを書式なしで貼り付けます。貼り付けたあと、クリップボードは元の内容に戻ります。
- **重複しない**: すでに履歴にある文字をもう一度コピーすると、前のものを消していちばん上に移します。
- **残す件数**: 10〜10,000 件（既定は 1,000 件）。超えると古いものから消えます。
  大きなものばかりをたくさん覚えてメモリや保存するファイルが大きくなりすぎないよう、履歴全体が
  32 MB を超えたときも古いものから消します（1 件は 5 万文字まで）。
- **終了しても残す**（既定は ON）: 履歴をファイル（`settings.json` と同じ場所の `clip_history.dat`）に
  保存し、次に起動したときに続きから使えます。ファイルは Windows の機能（DPAPI）で暗号化しており、
  **この PC の同じユーザーでなければ読めません**。OFF にすると、確かめてから、保存していたファイルを
  消し（ピン留めしたものも消えます）、履歴はアプリを終了すると消えるようになります。
  履歴そのものを OFF にしたときは、ファイルは消さずに残します（ON に戻すと、また使えます）。
- 保存したファイルを読めなかったとき（別の PC・別のユーザーで保存したもの、壊れたもの）は、空の履歴から
  始め、読めなかったファイルは `clip_history.unreadable.dat` という名前で残します。
- **履歴をすべて削除**: 設定画面の「履歴をすべて削除...」で、保存したものも含めて消します
  （ピン留めしたものは残ります）。
- **履歴に残さないアプリ**: 設定画面の「履歴に残さないアプリ」にプロセス名を空白で区切って書くと
  （例 `KeePass.exe 1Password.exe`）、そのアプリでコピーしたものは履歴に残しません。横の
  「アプリを選ぶ...」で、開いているアプリから選んで足せます。
- 記録するのは文字と画像です（ファイルのコピーは記録しません）。パスワード管理ソフトなどが
  「記録しないで」と印を付けた内容（Windows のクリップボードの履歴に残らないもの）は記録しません。
  1 件が 5 万文字を超えるものも記録しません。

### 画像の履歴

スクリーンショット（`PrintScreen`・Snipping Tool など）や、ブラウザーなどでコピーした画像も履歴に残り、
一覧の「画像」タブから貼り付けられます（設定画面の「画像（スクリーンショットなど）も履歴に残す」。
既定は ON）。

- **一覧**: 1 行に、画像の大きさ（例 `1920×1080`）とコピーした日時を出します。選ぶと、横に画像を
  表示します。帯の表示では、カードに画像そのものを出します。
- **貼り付け**: 選んだ画像を、画像として貼り付けます（Excel・Word・PowerPoint・ペイント・チャットなど）。
  貼り付けたあと、クリップボードは元の内容に戻ります。画像を受け取らない入力欄（メモ帳など）では、
  画面に「不可」と短く出ます。
- **件数と容量**: 件数は文字の「残す件数」と同じです。保存した大きさの合計が 500 MB を超えたときも、
  古いものから消します。ピン留めした画像（最大 200 枚）は、どちらでも消えません。
- **保存**: 画像は 1 枚ずつ圧縮し、文字の履歴と同じ方法（DPAPI）で暗号化して、`data\clip_images`
  フォルダに置きます（この PC の同じユーザーでなければ読めません）。「アプリを終了しても履歴を残す」が
  OFF のときは、終了するときに消します。
- **文字と画像の両方があるコピー**（Excel のセルなど）は、文字として記録します。
- 同じ画像をもう一度コピーすると、増やさずにいちばん上に移します。1 枚が 128 MB（圧縮前）を超える
  画像は記録しません。
- ピン留め（`P`）・1 件を消す（`Delete`）・「履歴をすべて削除」は、文字の履歴と同じです。

### 一覧の出し方

設定画面の「出す位置」で、一覧の形を選べます。

| 出す位置 | 形 |
| --- | --- |
| 入力位置の近く（既定） | 小さな縦の一覧。入力位置が分からないアプリではマウスの近く |
| マウスの近く | 同じ一覧を、マウスカーソルの近くに |
| 画面の右端に縦のパネル | 画面の右端に、上から下までの縦のパネル。一度にたくさんの件数を見渡せます |
| 画面の下に横長の帯 | 画面の下に、カードを横に並べます。文字は数行、画像は絵そのものが見えます |

- 帯では、左右の矢印キーで選び、上下の矢印キーでタブを切り替えます（ほかの形ではその逆）。
  長い文字や画像は、選んだカードの上に大きく出します。
- 「幅」と「1 ページの件数」は、小さな縦の一覧のときの値です（パネルと帯は、画面の大きさに合わせて
  件数を決めます。パネルの幅は、設定の幅と 300 px の大きい方です）。

一覧を出す操作は、次から選べます。

| 一覧を出す操作 | 内容 |
| --- | --- |
| キーの組み合わせ（既定） | `Ctrl` / `Shift` / `Alt` / `Win` とキーの組み合わせ。既定は `Ctrl+Alt+H` |
| Ctrl を素早く 2 回押す | `Ctrl` だけを 2 回、決めた間隔（既定 0.4 秒、0.2〜1 秒）の中で押して離す |
| Shift を素早く 2 回押す | 同じく `Shift` |
| Alt を素早く 2 回押す | 同じく `Alt` |

- 2 回押しは、そのキーだけを短く押したときに数えます（`Ctrl+C` のようにほかのキーと組み合わせた押し方、
  `Ctrl+クリック` のようにマウスと組み合わせた押し方、長押し、AltGr は数えません）。キーそのものは
  アプリにもそのまま届きます。
- 一覧を出すキーは、トレイメニューの「キー割り当て」を OFF にしていても効きます。値貼り付けのキーや
  キー割り当てと同じキーにはできません（保存するときに知らせます）。
- キー割り当ての動作「クリップボードの履歴から貼り付け」でも、同じ一覧を出せます
  （別のキーでも出したいとき）。件数などは上の設定に従います。
- Windows 標準のクリップボードの履歴（`Win+V`）とは別のものです。

`settings.json` では次のように書きます。

```jsonc
{
  "clipboard_history": {
    "enabled": true,
    "trigger": "double_ctrl",   // "hotkey" / "double_ctrl" / "double_shift" / "double_alt"
    "hotkey": "Ctrl+Alt+H",     // trigger が "hotkey" のとき
    "double_tap_ms": 400,       // 2 回押しの間隔（200〜1000 ミリ秒）
    "max_items": 1000,          // 10〜10000
    "keep_after_exit": true,
    "position": "caret",        // "caret"（入力位置の近く）/ "mouse" / "side"（右端のパネル）/ "bottom"（下の帯）
    "keep_open": false,         // 貼り付けても一覧を出したままにする
    "record_images": true,      // 画像も履歴に残す
    "width": 260,               // 一覧の幅（200〜600。96 DPI 基準のピクセル）
    "opacity": 90,              // 不透明度（30〜100 %）
    "page_size": 20,            // 1 ページの件数（10〜40）
    "theme": "system",          // "system" / "light" / "dark" / "blue" / "green"
    "move_to_top": true,        // 一覧から貼り付けたものを、いちばん上に移す
    "exclude_apps": []          // 履歴に残さないアプリ（例 ["KeePass.exe"]）
  }
}
```

### キーの組み合わせの決まり

- 英字・数字のキーには `Ctrl` か `Alt` を組み合わせてください。単独や `Shift` だけでは、
  普段の文字入力ができなくなるため保存できません。`F1`〜`F12` は単独でも使えます。
- `Ctrl+Shift+V` は値貼り付けそのものなので登録できません。
- 押されている修飾キーが**ちょうど一致したときだけ**反応します（`Ctrl+B` の設定で
  `Ctrl+Shift+B` を押しても反応しません。`Win` キーを押しているときも反応しません）。
- `Alt` を含む組み合わせでは、アプリのメニュー（Excel ではリボンのキー操作）が開かないよう、
  `Alt` を離す操作の前に、何も割り当てられていないキー（仮想キー `0xE8`）を 1 回送ります。
- その組み合わせがもともと持っていた機能（例: `Ctrl+Q`）は、対象アプリの中では使えなくなります。

### 対象アプリの書き方

- 欄の横の「アプリを選ぶ...」を押すと、いま開いているアプリの一覧（プロセス名と、ウィンドウの題名）が出ます。
  使いたいアプリを開いておき、一覧から選んで「追加」を押すと（ダブルクリックでも可）、そのプロセス名が欄に
  足されます。設定画面の対象アプリ・履歴に残さないアプリと、キー割り当て画面の対象アプリで使えます。
- 管理者として動いているアプリは名前を取れないため、一覧に出ません（そのアプリではキーの置き換えも効きません）。
- 一覧のほか、タスクマネージャーの「詳細」タブの「名前」の列でも確かめられます。
- 大文字・小文字は区別しません。`.exe` は省略でき、フォルダ付きで書いてもファイル名だけを使います。
- 名前に空白を含む場合は `"My App.exe"` のように `"` で囲んでください。

### settings.json での設定

設定画面の内容は `settings.json` に次のように保存されます（他の項目はそのまま残します）。
直接編集した場合は、アプリを再起動すると反映されます。使えないキーが書かれていた場合は
`Ctrl+B` で動き、対象アプリが空の場合は `EXCEL.EXE` で動きます。

```jsonc
{
  "remap": {
    "hotkey": "Ctrl+B",              // 例: "Ctrl+Shift+B"、"Alt+Q"、"F12"
    "target_apps": ["EXCEL.EXE"]
  }
}
```

## 定型文

よく使う文（あいさつ・住所・口座番号など）を登録しておき、クリップボードの履歴の一覧の「定型文」タブ
から選んで貼り付けられます。

- **登録・編集**: トレイメニューの「定型文の編集...」（または一覧の右クリック「定型文の編集...」）で開く
  画面で、「新規」を押して名前と本文を書き、「新しい定型文として追加」を押します。直すときは一覧で選んで
  書き換え、「選んだ定型文に上書き」を押します。最後に「OK」を押すと保存します。名前を空にすると、
  本文の最初の行を一覧に出します。書きかけのまま「OK」や別の行を選んだときは、確かめるメッセージが出ます。
- **履歴から登録**: 履歴の一覧で右クリック →「定型文に登録」で、その履歴をそのまま定型文に足します
  （同じ本文がすでにあれば足しません）。履歴の文字にある `{` `}` は、そのまま貼り付けられるよう
  `{{` `}}` にして登録します。
- **キーで直接貼り付け**: キー割り当ての動作「定型文を貼り付け」で、名前（一覧に出ている名前）を
  書いておくと、そのキーで一覧を出さずにすぐ貼り付けます。名前が見つからないときは画面に「なし」と出ます。
  名前で選ぶので、同じ名前の定型文が 2 つあると上にあるものだけが貼り付けられます（同じ名前で追加・
  上書きしようとすると知らせます）。
- **日付・時刻**: 本文の `{date}` は今日の日付（`2026/10/08`）、`{time}` は今の時刻、`{datetime}` は
  両方に置き換えて貼り付けます。`{` そのものは `{{`、`}` は `}}` と書きます。
- **CSV**: 「CSV から読み込む...」「CSV に書き出す...」で、Excel などでまとめて編集できます。
  1 列目が名前、2 列目が本文です（1 行目に「名前,本文」の見出しがあれば飛ばします。1 列だけなら本文
  として読みます）。読み込みは UTF-8 と Shift_JIS（Excel の「CSV（コンマ区切り）」）のどちらでも
  かまいません。書き出しは UTF-8 です。
- 最大 1,000 件、1 件の本文は 2 万文字まで。`settings.json` の `snippets` に保存するので、
  [設定の引っ越し](#設定の引っ越し) にも含まれます。
- 定型文のタブは、クリップボードの履歴の一覧の中にあります。トレイメニューの「クリップボードの履歴」を
  ON にして使ってください。

## キー割り当て

トレイメニューの「キー割り当ての編集...」で開きます。「このキーを押したら、この動作をする」
という割り当てを、何個でも追加できます（AutoHotkey や PowerToys のキーボードマネージャーのような
使い方です）。「OK」を押すと保存して、**すぐに使えます**（再起動は要りません）。
すべての割り当てを一時的に止めたいときは、トレイメニューの「キー割り当て」のチェックを外します。

### 使い方

1. 「新規」を押し、右側の「割り当ての内容」で、キー・動作・内容・対象アプリを決めます。
2. 「新しい割り当てとして追加」を押すと、左の一覧に加わります。
3. 直したいときは、左の一覧で選んで右側を書き換え、「選んだ割り当てに上書き」を押します。
4. 「OK」を押します。右側に書きかけの内容があるときや、保存せずに閉じようとしたときは、
   確かめるメッセージが出ます。

一覧は上から順に調べ、最初に当てはまった割り当てだけを使います（「上へ」「下へ」で並べ替えられます）。
同じキーで同じアプリに効く割り当てが 2 つあると、保存するときに知らせます。
一時的に止めたい割り当ては「この割り当てを使う」を外します（一覧に［停止中］と出ます）。

**書き出しと読み込み**: 「書き出す...」で、一覧にある割り当てをファイル（JSON）に保存します。
ほかの PC では「読み込む...」でそのファイルを選び、今の割り当ての後ろに足すか、置き換えるかを選びます。
`settings.json` そのものも読み込めます。読み込んだ割り当ても、「OK」を押すまでは使いません。

**一覧の表示**: トレイメニューの「キー割り当ての一覧」（またはその動作を割り当てたキー）で、値貼り付けの
キーとすべてのキー割り当てを一覧で表示します。どのキーに何を割り当てたか忘れたときに使います。

### 動作の種類

| 動作 | 内容に書くもの | 使い方の例 |
| --- | --- | --- |
| キーを送る | 送るキー。カンマで区切ると順に送る | `F9` → `Ctrl+Alt+V, V, Enter`（「形式を選択して貼り付け」で値だけを貼る。`Ctrl+Shift+V` が無い Excel 2019 / 2021 向けの代わりとして） |
| 文字を入力する | 入力する文字（改行も可） | `Ctrl+Alt+D` → `{date}`（今日の日付を入力） |
| プログラムやファイル・URL を開く | 開くもの（と引数） | `Ctrl+Alt+N` → `notepad.exe` |
| 書式なしで貼り付け | （なし） | `Ctrl+Alt+V` → Web や Word からコピーした文字を、文字だけ貼り付ける |
| 文字を整えて貼り付け | 整え方（チェックで選ぶ） | `Ctrl+Alt+T` → 全角の数字や `▲1,200` を `-1200` にして貼る（下記） |
| 定型文を貼り付け | 定型文の名前 | `Ctrl+Alt+1` → `あいさつ`（一覧を出さずに、その定型文をすぐ貼る） |
| クリップボードの履歴から貼り付け | （なし） | `Ctrl+Alt+Y` → 少し前にコピーしたものを選んで貼る（下記） |
| キー割り当ての一覧を表示 | （なし） | `Ctrl+Alt+L` → 割り当てたキーを忘れたときに |
| 前面のウィンドウを常に手前に表示 | （なし） | `Win+Shift+T` → 押すたびに切り替え（画面に「固定」「解除」と出ます） |
| 何もしない（キーを無効にする） | （なし） | `F1`（Excel だけ）→ うっかりヘルプを開かないように |

- **キー**: `Ctrl` / `Shift` / `Alt` / `Win` と、`A`〜`Z`・`0`〜`9`・`F1`〜`F24`・`Space`・`Enter`・`Tab`・
  `Esc`・`Backspace`・`Delete`・`Insert`・`Home`・`End`・`PageUp`・`PageDown`・矢印（`Left` / `Up` /
  `Right` / `Down`）の組み合わせ。`F1`〜`F24` 以外は、`Ctrl`・`Alt`・`Win` のどれかと組み合わせてください
  （単独や `Shift` だけでは、普段の入力ができなくなるため）。
- **文字を入力する**: `{date}` は今日の日付（`2026/10/05`）、`{time}` は今の時刻（`13:45`）、
  `{datetime}` は両方に置き換えます。`{` そのものは `{{`、`}` は `}}` と書きます。IME の状態に
  かかわらず、書いたとおりの文字を入力します。入れ方は 2 通りです。
  - **まとめて貼り付ける**（既定）: クリップボードを使って `Ctrl+V` で一度に貼り付け、そのあと元の
    クリップボードの内容へ戻します。長い文でも一瞬で入り、入力補完などに邪魔されません。
    一時的に入れた文字は、Windows のクリップボードの履歴（`Win+V`）には残しません。
    待っている間に別のものをコピーした場合は、それを消さないよう元に戻しません。
    **貼り付けを受け付けない入力欄では、自動で 1 文字ずつの入力に切り替えます**（下記）。
  - **1 文字ずつ**（「まとめて貼り付ける」を外す）: いつもキーを打ったときと同じように 1 文字ずつ送ります。
  - **貼り付けを受け付けるかの見分け方**: 文字そのものはクリップボードに置かず、「求められたら渡す」
    という予約（遅延レンダリング）だけを置いて `Ctrl+V` を送ります。貼り付け先が 0.5 秒以内に文字を
    読みに来たら渡し、来なければ受け付けない入力欄とみなして、クリップボードを元に戻してから
    1 文字ずつ入力します。予約の段階では文字を渡していないので、二重には入りません。
    ただし、`Ctrl+V` を受け付けない欄が `Ctrl+V` を別の意味に使っている場合（コンソールで `^V` と
    表示されるなど）は、その動きが起きたあとに 1 文字ずつ入力されます。また、クリップボードの中身を
    すぐに読む常駐ソフト（クリップボード管理ソフトなど）を使っていると、受け付けたと見なされることが
    あります（Windows 標準のクリップボードの履歴は読みに来ません）。
  - 貼り付けるので、Excel でセルを選んだだけの状態（編集中でない）に複数行の文を入れると、
    行ごとに下のセルへ分かれて入ります。
- **書式なしで貼り付け**: クリップボードの文字だけを取り出してクリップボードに入れ直し、`Ctrl+V` を
  送ります。そのため、**貼り付けたあとのクリップボードも文字だけになります**。
- **文字を整えて貼り付け**: クリップボードの文字を、チェックした整え方で直してから貼り付けます。
  **クリップボードの中身は変えません**（貼り付けたあと、元の内容に戻ります）。整え方は次の 10 種類で、
  チェックしたものを下の表の順に当てます。

  | 整え方 | 例 |
  | --- | --- |
  | 全角英数・記号を半角に | `ＡＢＣ１２３（株）` → `ABC123(株)`（全角の空白も半角に。`￥` はそのまま） |
  | 半角カタカナを全角に | `ｶﾞｷﾞｸﾞ` → `ガギグ` |
  | ▲ △ (123) をマイナスに | `▲1,200` `△50` `(300)` `（300）` → `-1,200` `-50` `-300` `-300`（▲ △ はすぐ後に数字があるときだけ。括弧は、行末・タブ・「円」の前など表の値らしいときだけで、`(1) 項目` や `f(2)` はそのまま） |
  | 桁区切りの , を除く | `1,234,567` → `1234567`（数字の間の 3 桁区切りだけ。`a,b` はそのまま） |
  | 各行の前後の空白を除く | 行ごとに、先頭と末尾の空白・タブを除く |
  | 空の行を除く | 何も書かれていない行を除く |
  | 続く空白を 1 つに | `A␣␣␣B` → `A␣B`（タブも空白として扱う） |
  | 空白をすべて除く | 空白・全角の空白・タブを除く |
  | 改行を除いて 1 行に | 複数行を 1 行につなげる |
  | 全体の前後の空白を除く | 全体の先頭と末尾の空白・改行を除く |

  例えば「全角英数・記号を半角に」「▲ △ (123) をマイナスに」「桁区切りの , を除く」を選ぶと、
  会計ソフトや PDF からコピーした `△１，２００` が `-1200` になり、Excel で数値として扱えます。
- **クリップボードの履歴から貼り付け**: [クリップボードの履歴](#クリップボードの履歴) の一覧を出します。
  設定画面で一覧を出す操作を決めていても、別のキーでも出したいときに使います。この割り当てがあれば、
  クリップボードの履歴を OFF にしていても、履歴に残します（件数などは設定画面の値に従います）。
- **対象アプリ**: 「すべてのアプリ」か、「指定したアプリだけ」（プロセス名を空白で区切って書く。
  例 `EXCEL.EXE WINWORD.EXE`）。「アプリを選ぶ...」で、開いているアプリから選んで足せます。
- 値貼り付け（`Ctrl+B`）のキーと同じキーは、値貼り付けが先に効くので使えません（保存するときに知らせます）。

### 注意

- **Windows が先に使うキーは割り当てられません**: `Ctrl+Alt+Delete`、`Win+L` など。
- **管理者として実行しているアプリ**の中では、キー割り当ては効きません（Windows の仕組みで、
  通常の権限のアプリからは操作できないため）。「常に手前に表示」も、そのウィンドウには効きません
  （画面に「不可」と出ます）。
- **そのキーがもともと持っていた機能**は、対象アプリの中では使えなくなります。
- `Alt` や `Win` を含むキーでも、離したときにメニューやスタートが開かないようにしています。
- **修飾キーを押したまま続けて使えます**: `Ctrl` や `Shift` を押したまま割り当てのキーを押し、そのまま
  別のキー（例: `Ctrl` を押したまま `S`）を押しても、`Ctrl+S` として効きます。
- **貼り付け先が固まっているとき**（再計算中の Excel など）は、応答するまで待ってから貼り付けます。
  10 秒待っても応答しないときは貼り付けをやめ、画面に「応答なし」と出します。
- 履歴の一覧を出している間に押したほかの割り当ては、実行しません。
- **キーを送る**は、書いたキーを間を空けずに続けて送ります。ダイアログを開くキーのあとに続けて
  操作する場合など、アプリによっては取りこぼすことがあります。

### settings.json での書き方

キー割り当ては `settings.json` の `hotkeys` に保存されます。直接編集した場合は、アプリを再起動すると
反映されます（読めない割り当ては使わず、[ログ](#ログトラブル調査用) に理由を残します）。

```jsonc
{
  "hotkeys": [
    { "hotkey": "Ctrl+Alt+V", "action": "paste_plain" },
    { "hotkey": "F9", "action": "send_keys", "value": "Ctrl+Alt+V, V, Enter", "apps": ["EXCEL.EXE"] },
    { "hotkey": "Ctrl+Alt+D", "action": "type_text", "value": "{date}" },
    { "hotkey": "Ctrl+Alt+S", "action": "type_text", "value": "よろしくお願いいたします。", "input": "keys" },
    { "hotkey": "Ctrl+Alt+N", "action": "run", "value": "notepad.exe", "args": "" },
    { "hotkey": "Ctrl+Alt+T", "action": "paste_transform", "value": "zen_to_han,negative_marks,remove_commas" },
    { "hotkey": "Ctrl+Alt+Y", "action": "clipboard_history" },
    { "hotkey": "Ctrl+Alt+L", "action": "show_list" },
    { "hotkey": "Win+Shift+T", "action": "toggle_topmost" },
    { "hotkey": "F1", "action": "block", "apps": ["EXCEL.EXE"], "enabled": false }
  ]
}
```

`action` は `send_keys` / `type_text` / `run` / `paste_plain` / `paste_transform` / `paste_snippet` /
`clipboard_history` / `toggle_topmost` / `show_list` / `block` のどれかです（`paste_snippet` の `value` は
定型文の名前）。`paste_transform` の `value` には、整え方を
カンマで区切って書きます（`zen_to_han`（全角英数・記号を半角に）/ `han_kana_to_zen` / `negative_marks` /
`remove_commas` / `trim_lines` / `remove_blank_lines` / `collapse_spaces` / `remove_spaces` /
`join_lines` / `trim`。書いた順にかかわらず、上の表の順に当てます）。
`enabled` を省くと使う（`true`）扱い、`apps` を省くとすべてのアプリです。`input` は「文字を入力する」の
入れ方で、`"paste"`（まとめて貼り付ける。省いたとき）か `"keys"`（1 文字ずつ）です。

## 入力モードの表示

`半角/全角` キーやカタカナへの切り替えなどで IME の入力モードを変えると、画面に
モードを大きく表示します（既定では画面中央に 0.4 秒表示したあと 0.25 秒で消えます。
出し方は [設定画面](#設定画面) で変えられます）。

- **表示する文字**: `あ`（ひらがな）、`カ`（全角カタカナ）、`ｶ`（半角カタカナ）、
  `Ａ`（全角英数）、`A`（半角英数・IME オフ）
- **表示するとき**: 同じウィンドウの中でモードが変わったときだけ。`Alt+Tab` などで
  モードの違うウィンドウへ移っただけでは表示しません。
- **表示する場所**: 次の 3 つから選べます。大きさはモニターの拡大率（DPI）に合わせます。
  - **画面中央**（既定）: 前面ウィンドウがあるモニターの中央（タスクバーを除いた領域）
  - **マウスの近く**: マウスカーソルの右下（画面の端では左や上へずらします）
  - **入力位置の近く**: 文字を入力している位置（キャレット）の右下。ブラウザーなど、
    入力位置を Windows に知らせないアプリでは取れないため、画面中央に表示します
- **配色と不透明度**: 「ダーク」（濃いグレーに白い文字。既定）と「ライト」（明るいグレーに
  濃い文字）から選べます。不透明度は 30〜100 % です（既定 90 %）。
- **全画面のアプリの間は表示しない**: ON にすると、ゲーム・動画の全画面再生・
  プレゼンテーションの間は表示しません（Windows がそう判断している間。既定は OFF）。
- **操作の邪魔をしない**: 表示はクリックを下のウィンドウへ素通しし、フォーカスも奪いません。
  タスクバーにも出ません。
- **状態が取れないとき**: 管理者権限で動いているウィンドウなど、IME の状態を読み取れない
  相手では何も表示しません。

### いまの入力モードを小さな印で出す

切り替えた瞬間の表示とは別に、いまの入力モードを小さな印で出せます。入力するときに、
日本語入力か英字入力かを目で確かめられます。設定画面の「入力モード」タブで
「いまの入力モードを、小さな印で出す」にチェックを付けると使えます（既定は OFF）。

- **出すとき**: 次から選べます。
  - **おまかせ**（既定）: 打つ前に気づけて、読んでいる間は邪魔にならないようにします。
    - 入力欄に入力位置（点滅するカーソル）がある間は、その横に出し続けます。入力欄を選んでいない
      間（ボタンや本文をクリックしたあとなど）は出ません。入力位置は、Windows のキャレットに加えて、
      アプリがアクセシビリティの情報として知らせる入力位置からも調べるので、ブラウザーや、その
      仕組みで作られたアプリの多くでも分かります。
    - 入力位置が分からないアプリでは、文字を打つ場所だと分かるときにだけ、マウスカーソルの横に出し、
      決めた時間（既定 3 秒。1〜10 秒）がたつと消えます。きっかけは、マウスカーソルが文字入力の形
      （I の形）のときにクリックしたとき、その形に変わったとき、文字のキーを打ったとき、モードを
      切り替えたときです。ボタンや余白のクリック、ウィンドウの切り替えでは出ません。
    - マウスカーソルの形で出すのが気になるとき（ブラウザーでは、読める文字の上でも I の形に
      なります）は、「マウスカーソルが文字入力の形（I）になったら出す」を OFF にできます。
      独自のカーソルを使うアプリでは、形の変化は分かりません。
    - 「出す場所」が「マウスカーソルの横」のときは、どのアプリでも、打ちそうなときだけ出します。
  - **打ち始めたときだけ**: 文字のキーを打ったとき、入力欄をクリックしたとき（入力位置が分かる
    アプリ）、モードを切り替えたときに出し、決めた時間がたつと消えます。
  - **出し続ける**: 入力モードを読み取れる間、ずっと出します。
  - `Ctrl+C` のようなショートカットや、`Shift` などを押しただけでは、きっかけになりません。
- **不透明度**: 20〜100 %（既定 90 %）。薄くすると、下の文字が透けて見えます。

- **印の見た目**: 日本語入力（`あ` `カ` `ｶ` `Ａ`）は赤、英字入力（`A`）は青の、角の丸い四角に
  白い文字で出します。文字を読まなくても色で見分けられます。
- **出す場所**: 次から選べます。
  - **入力位置の横**（既定）: 文字を入力している位置（キャレット）のすぐ右下。入力位置を
    Windows に知らせないアプリ（ブラウザーなど）では、マウスカーソルの横に出します
  - **マウスカーソルの横**: マウスカーソルの右下に付いて動きます
- **大きさ**: 12〜48 px（既定 20 px。モニターの拡大率に合わせます）。
- 「切り替えたときに、画面に大きく表示する」を OFF にすれば、小さな印だけを使えます。
  メニューの「入力モードの表示」を OFF にすると、両方とも出しません。
- 全画面のアプリの間は表示しない設定・IME の状態を読み取れない相手・日本語以外の入力方式の
  扱いは、大きな表示と同じです。クリックは下のウィンドウへ素通しします。
- **日本語の入力方式のときだけ**: 韓国語や中国語の入力方式を使っている間は表示しません。

前面ウィンドウの入力欄の IME 状態を 100ms ごとに調べています（`ImmGetDefaultIMEWnd` で
得た IME ウィンドウへ `WM_IME_CONTROL` を `SendMessageTimeoutW` で問い合わせるため、
相手が固まっていても巻き込まれません）。

### 設定

[設定画面](#設定画面) で変えられます。値は `settings.json` の `ime_indicator` に保存され、
メニューで切り替えた ON/OFF もここに保存されます（ファイルの他の内容はそのまま残します）。

```jsonc
{
  "ime_indicator": {
    "enabled": true,   // false で表示しない
    "hold_ms": 400,    // 消え始めるまでの表示時間（ミリ秒。100〜5000）
    "fade_ms": 250,    // フェードアウトにかける時間（ミリ秒。0〜2000。0 ですぐ消す）
    "size": 120,       // 表示の一辺（拡大率 100% のときのピクセル。40〜600）
    "position": "center",  // "center"（画面中央）/ "mouse"（マウスの近く）/ "caret"（入力位置の近く）
    "theme": "dark",   // "dark"（ダーク）/ "light"（ライト）
    "opacity": 90,     // 不透明度（%。30〜100）
    "hide_in_fullscreen": false, // true で全画面のアプリの間は表示しない
    "flash": true,     // false で、切り替えたときの大きな表示をしない
    "badge_enabled": false, // true で、いまの入力モードを小さな印で出す
    "badge": "caret",  // 小さな印を出す場所: "caret"（入力位置の横）/ "mouse"（マウスカーソルの横）
    "badge_size": 20,  // 小さな印の一辺（拡大率 100% のときのピクセル。12〜48）
    "badge_when": "auto",   // 小さな印を出すとき: "auto"（おまかせ）/ "typing"（打ち始めたときだけ）/ "always"（出し続ける）
    "badge_hold_ms": 3000,  // きっかけのあと出しておく時間（ミリ秒。1000〜10000）
    "badge_opacity": 90,    // 小さな印の不透明度（%。20〜100）
    "badge_on_ibeam": true  // 「おまかせ」のとき、マウスカーソルが文字入力の形になったら出す
  }
}
```

設定画面で保存した場合はすぐに反映されます。`settings.json` を直接編集した場合は、
アプリを再起動すると反映されます。

### Windows 標準の中央表示との二重表示を避ける

Windows にも同じような「入力モードを画面中央に表示する」機能があり、両方が有効だと
二重に表示されます。こちらを使う場合は、Windows 側を次の手順でオフにしてください。

1. タスクバーの入力モード表示（`あ` や `A`）を右クリックし、「設定」を開く
   （Windows 11 では「設定」→「時刻と言語」→「言語と地域」→ 日本語の「…」→
   「言語のオプション」→ Microsoft IME の「…」→「キーボード オプション」でも開けます）。
2. 「全般」を開く。
3. 「IME 入力モード切替の通知」の「画面中央に表示する」をオフにする。

項目の名前や場所は Windows のバージョンによって少し異なる場合があります。

## ログ（トラブル調査用）

「キーが効かない」「入力モードが表示されない」などのときの調査のために、アプリの動作を
`log.txt` に残せます。**既定では残しません。**

1. 設定画面の「全般」タブで「動作のログを保存する（log.txt）」を ON にして「適用」を押します
   （再起動は要りません。その時点のバージョンと設定を最初に書きます）。
2. うまく動かない操作をもう一度行います。
3. 同じタブの「ログを開く」で `log.txt` を開き、内容を確かめます（問い合わせの際に添えてください）。
4. 調べ終わったら OFF に戻します。

ログに残す内容:

- 起動時のバージョン・実行ファイルと設定ファイルの場所・設定の内容
- 設定したキーを押したときに、値貼り付けを送ったか、送らなかった理由（OFF だった・前面の
  アプリが対象外だった。対象外のときはそのアプリのプロセス名）
- 入力モードを表示したこと、IME の状態を読み取れないアプリ（アプリごとに最初の 1 回だけ）
- 更新の確認の結果、エラー

**入力した文字は残しません**（キーボードについて残すのは、設定したキーの組み合わせを
押したときだけです）。ただし、ファイルの場所（ユーザー名を含むことがあります）は記録します。

`log.txt` は `settings.json` と同じフォルダ（実行ファイルの下の `data` フォルダ）に置きます。1 MB を超えると `log.old.txt` に
回して新しく作り直すので、大きくなり続けることはありません。

## 自動更新

新しいバージョンが公開されたら、アプリ内から更新できます。

### 新しいバージョンが見つかったときの動き

設定画面の「全般」タブの「新しいバージョンが見つかったら」で選びます。

| 選択 | 動き |
| --- | --- |
| 尋ねてから更新する（既定） | 「今すぐ更新しますか？」と尋ね、「はい」なら入れ替えて再起動します |
| 尋ねずに更新する | 尋ねずにダウンロードと検証を済ませ、**2 分ほど操作が無く、設定画面・キー割り当て画面・定型文の画面・履歴の一覧のどれも開いていないとき**に入れ替えて再起動します。再起動したら、トレイの通知で「更新しました」と知らせます。ダウンロードや入れ替えに失敗しても画面には出さず、次の確認でまた試します。待っている間に「更新を確認」を押すと、ダウンロード済みで入れ替えを待っていることを知らせます |
| 知らせるだけ | 新しいバージョンが出たことだけを知らせます。更新はトレイメニューの「更新を確認」から行います |

トレイメニューの「更新を確認」を押したときは、どの設定でも「今すぐ更新しますか？」と尋ねます。
起動している間の確認では、すでに尋ねて見送った版・知らせた版を、もう一度は出しません
（アプリを起動し直すと、また尋ねます）。

### 通信するタイミング

このアプリが外部と通信するのは、**次の 3 つの場合だけ**です。それ以外では一切通信しません。

| きっかけ | 内容 |
| --- | --- |
| メニュー「更新を確認」を押したとき | 最新リリースを問い合わせる |
| 起動時（**毎回**） | 起動のたびに最新リリースを問い合わせる |
| 起動している間（**6 時間おき**） | 前回の確認から 6 時間経っていれば問い合わせる（10 分おきに時刻を確かめる。スリープしていた間も時計で数える） |

通信は必ず別スレッドで行うため、起動やキー操作を妨げません。失敗しても
「確認できなかった」で済ませ、アプリの動作には影響しません。

タイムアウトも明示しています。確認（Atom / API とも）は **15 秒**、
更新ファイルのダウンロードは、1 分応答が無いか、全体で **10 分**を超えたら打ち切ります。
確認に失敗した回は「確認した」と数えないので、次の機会（10 分後）にまた試します。

### 通信先と GitHub API のレート制限対策

GitHub の Releases API（`https://api.github.com/...`）には未認証の場合
**1 時間 60 回**という上限があり、これは端末ごとではなく **IP アドレスごと**に
数えられます。会社などの共有回線では他の通信で先に使い切られてしまい、
更新確認のたびに HTTP 403 が返ることがあります。

`https://github.com/{owner}/{repo}/releases.atom`（Atom フィード）はこの上限とは
**別枠**であるため、このアプリは次の順で確認します。

1. まず Atom フィードで最新のタグだけを確認する。ここで「最新である」と
   分かれば、API は呼ばずに終える（レート制限を消費しない）。
2. Atom で**新しい版が見つかったときだけ**、添付ファイルの詳細
   （ダウンロード URL・SHA256）を取りに API を呼ぶ。呼ぶ頻度が
   「更新があったとき」だけになるので、上限に当たる見込みはほぼ無くなる。
3. その API が失敗しても（403 を含む）、Atom で新しい版があると分かって
   いれば、ダウンロード URL は規則から組み立て
   （`https://github.com/{owner}/{repo}/releases/download/{tag}/{asset_name}`）、
   SHA256 はリリースのページが読み込む添付ファイルの一覧
   （`https://github.com/{owner}/{repo}/releases/expanded_assets/{tag}`。API の
   回数制限の枠を使わない）から取って更新を続行する。SHA256 が取れなければ、
   その回の更新は見送ります（下記「SHA256 の検証について」を参照）。

| 用途 | URL |
| --- | --- |
| 更新の確認（優先） | `https://github.com/Yu5rin/MyPaste/releases.atom` |
| 更新の確認（詳細・新しい版があるときのみ） | `https://api.github.com/repos/Yu5rin/MyPaste/releases/latest` |
| SHA256 の取得（API が使えないときのみ） | `https://github.com/Yu5rin/MyPaste/releases/expanded_assets/{タグ}` |
| 更新の取得 | 上記いずれかの応答から得られる `https://github.com/...` のダウンロード URL |

更新ファイルの取得先は、応答をそのまま信用せず
**`github.com` / `api.github.com` / `objects.githubusercontent.com` /
`*.githubusercontent.com`（すべて HTTPS）に限定**しています。EXE を取得して
そのまま実行する処理のため、想定外のホストが混入しても取得自体を行いません。

**通信先は `settings.json` に書かれており、利用者が確認・変更できます。**
起動時に自動生成されるので、内容を見れば「どこへ通信するのか」が分かります。
Atom フィードの URL は `api_url` から自動的に組み立てます。`api_url` の
ホストが `api.github.com` でない場合（配布元を差し替えている場合など）は
Atom による確認をせず、従来どおり API だけで確認します。

```jsonc
{
  "update": {
    "check_on_startup": true,   // false にすると起動時の確認をやめ、手動のみになる
    "check_interval_hours": 0,  // 0 は起動のたびに確認。24 にすると 1 日 1 回までになる
    "check_every_hours": 6,     // 起動している間に確認する間隔（時間）。0 で確認しない
    "mode": "ask",              // 新しいバージョンが見つかったら: "ask"（尋ねてから更新）/ "auto"（尋ねずに更新）/ "notify"（知らせるだけ）
    "api_url": "https://api.github.com/repos/Yu5rin/MyPaste/releases/latest",
    "releases_page": "https://github.com/Yu5rin/MyPaste/releases/latest",
    "asset_name": "Atai-paste.exe"
  }
}
```

`settings.json` と `update_state.json`（前回の確認時刻）は、実行ファイルの下の `data` フォルダに
置かれます（[設定や記録を置く場所](#設定や記録を置く場所) を参照）。

### 更新の流れ

1. 上記の順（Atom → 必要なら API）で最新の `tag_name` を取得し、現在の
   バージョンと**数値として**比較します（文字列比較では `1.0.10` < `1.0.9`
   と誤判定するため）。
2. 新しい版があれば、設定（「新しいバージョンが見つかったら」）に従って、確認のダイアログを表示します
   （尋ねずに更新するときは出しません。知らせるだけのときは、ここで終わります）。
3. 「はい」を選ぶと（尋ねずに更新するときはすぐに）実行ファイルをダウンロードし、
   SHA256 で検証します（下記参照）。進捗はトレイアイコンのツールチップに表示されます。
4. 検証を通ったら実行ファイルを入れ替え、新しい版を起動して自分は終了します
   （尋ねずに更新するときは、操作が無くなるのを待ってから入れ替えます）。

ダウンロードした一時ファイルは、**入れ替えの成否にかかわらず削除**します。
書き出しが途中で失敗した場合も中途半端なファイルを残しません。強制終了などで
万一残った場合に備えて、起動時に一時フォルダの古い残骸（1 時間以上前のもの）も
掃除します。削除対象は `Atai-paste-<バージョン>.exe` という名前のものだけで、
本体の実行ファイルや無関係なファイルには触れません。

### SHA256 の検証について

ダウンロードしたファイルは、GitHub が添付ファイルごとに付けている SHA256
（`digest`。`sha256:...`）と突き合わせて検証します。SHA256 は GitHub Releases API から
取り、API が使えないとき（前述のレート制限で 403 になった場合など）は、リリースの
ページが読み込む添付ファイルの一覧から取ります。

API が使えず、一覧からも SHA256 を取れなかったときは、**検証できないものは入れず、
その回の更新を見送ります**（次の確認で、改めて試します）。その旨はログに残します。

API は使えたのに添付ファイルに `digest` が付いていない（一覧にも無い）ときも同じで、
検証できないものは入れません。通信は HTTPS（Windows 標準の WinHTTP、証明書の検証は OS に
任せる）で行い、ダウンロード元のホストは GitHub のリリース配信ホストに限り、先頭 2 バイトが
`MZ` であることも確かめます。試験版（`v1.9.0-beta` のように `-` が付くタグ）は、最新版として扱いません。

### 実行中の EXE を入れ替える仕組み

実行中の EXE は Windows がロックしているため上書きできませんが、**リネームはできます**。
そこで次の順で入れ替えます。

1. 新しい実行ファイルを、同じフォルダに `Atai-paste.exe.new` としてコピーで書き出す
2. `Atai-paste.exe` → `Atai-paste.exe.old` にリネーム
3. `Atai-paste.exe.new` → `Atai-paste.exe` にリネーム
4. 新しい EXE を起動して、自分は終了
5. 次回起動時に `.old` を削除

時間のかかる「コピー」を 1 で先に済ませておき、実際の入れ替え（2→3）は
リネーム 2 回だけで行います。リネームは同一ボリューム上ならほぼ一瞬で終わるため、
実行ファイルが存在しない瞬間はごく短くなります。

**保証されること**: 3 のリネームが失敗したことを検知できた場合は 2 を巻き戻すため、
アプリのプロセスが動き続けている限り壊れた状態にはなりません。

**保証されないこと**: 電源断や強制終了など、**OS ごと落ちるケース**では巻き戻しの
コード自体が実行されないため、上記の保証は成立しません。この窓（2 と 3 の間）で
中断されると、`Atai-paste.exe` が存在せず `.old` と `.new` だけが残った状態になり得ます。
このときはアプリを起動できなくなるので、**`Atai-paste.exe.old` の名前を `Atai-paste.exe` に戻して**
ください（リネーム 2 回の間のごく短い時間だけ起こり得ます）。

また `Program Files` 配下など書き込めない場所では自動更新を行いません。新しい版が見つかった時点で
書き込めるかを確かめ、書き込めなければダウンロードせずに「自動では更新できません。リリースページを
開きますか？」と案内します（「尋ねずに更新する」を選んでいても同じです。「知らせるだけ」なら知らせるだけ）。
起動している間の確認では、一度案内した版をもう一度は出しません。

終了処理（トレイメニューの「終了」）は、更新の入れ替え中であれば完了を
（最大 60 秒まで）待ってから行います。これにより、通常の操作で入れ替えの
途中にプロセスが終了することはありません。ダウンロードの途中で「終了」を選んだときは、
ダウンロードをやめて、入れ替えずに終了します。

## ビルド

Windows（MSVC ツールチェーン推奨）で以下を実行します。

```powershell
# 開発ビルド（コンソール表示あり・常に log.txt に記録）
cargo build

# 本番ビルド（コンソール非表示・記録は設定で ON にしたときだけ・サイズ最適化）
cargo build --release
```

生成物: `target/release/Atai-paste.exe`（単体で配布可能）。

### ビルドに関する補足

- アイコン（`src/icons/*.ico`）とマニフェスト（`app.manifest`）は、`build.rs` から
  [`embed-resource`](https://crates.io/crates/embed-resource) 経由で `app.rc` を
  コンパイルし、EXE に埋め込みます。MSVC 環境では Windows SDK の `rc.exe` が使われます。
- 設定にかかわらず常に記録する本番ビルドが欲しいときは、`--features devlog` を付けます。

```powershell
cargo build --release --features devlog
```

### GitHub Actions（手動実行のみ）

`.github/workflows/` の CI / Release ワークフローは自動実行せず、**Actions タブから手動実行**する設定（`workflow_dispatch`）です。

- **CI**: 手動実行すると `clippy` + リリースビルドを行い、`Atai-paste.exe` を Artifact として保存します。
- **Release**: タグ（例 `v1.0.0`）を入力して手動実行すると、EXE をビルドし、`RELEASE_NOTES.md`（変更点）に
  ダウンロードの表（ファイル・サイズ・SHA256）と README への案内を足した本文で、タグと同じ名前の GitHub Release を作成・添付します。

> ローカルに Windows 環境がある場合は、これらを使わず `cargo build --release` で直接ビルドできます。

## 技術仕様

| 項目 | 内容 |
| --- | --- |
| 言語 | Rust（edition 2021） |
| フック | `WH_KEYBOARD_LL`（低レベルキーボードフック） |
| キー送出 | `SendInput` API |
| 設定画面 | Win32 の標準コントロール（Common Controls v6）。Per-Monitor V2 の高 DPI 対応 |
| キー割り当て | 低レベルキーボードフックで捕まえ、別スレッドで実行。キー送出・文字入力は `SendInput`（文字は `KEYEVENTF_UNICODE`）、起動は `ShellExecuteW`、書式なし貼り付けはクリップボード（`CF_UNICODETEXT`）、履歴の記録は `AddClipboardFormatListener`、履歴の保存は DPAPI（`CryptProtectData`）、履歴の一覧はオーナードローのリストボックス、最前面は `SetWindowPos(HWND_TOPMOST)` |
| 対象アプリの判定 | `GetForegroundWindow` + `GetWindowThreadProcessId` + `OpenProcess` + `QueryFullProcessImageNameW` |
| タスクトレイ | `Shell_NotifyIconW` とポップアップメニュー（外部クレートなし）。エクスプローラーが再起動しても登録し直す |
| 自動起動 | スタートアップフォルダの `.lnk`（`IShellLinkW` / `IPersistFile`） |
| HTTPS 通信 | Windows 標準の **WinHTTP**（証明書の検証は OS に任せる） |
| 更新の検証 | SHA256（`sha2` クレート）。取得できないときは更新しない（上記「SHA256 の検証について」参照） |
| ログ | `log.txt`（設定で ON にしたとき・開発時）。`log` クレートのロガーを自前で実装し、専用のスレッドで書く |

通信に WinHTTP を使っているのは、証明書ストアを自前で抱えずに済み、
C やアセンブリのビルドを伴う TLS クレート（rustls / OpenSSL 系）を避けられるためです。
システムのプロキシ設定にも自動で従います。

### スレッド構成

- **フックスレッド**: `WH_KEYBOARD_LL` を設置し、メッセージループを回します。
  低レベルフックのコールバック配信にはメッセージループが必須です。
- **メインスレッド**: メニュー操作をチャネル経由で受け取り、アイコン切替・自動起動切替・
  終了処理を行います。
- **トレイスレッド**: タスクトレイのアイコンとメニューを受け持ち、独自のメッセージループを回します。
  選ばれた項目をチャネルでメインスレッドへ送ります。
- **ログスレッド**: `log.txt` への書き込みを受け持ちます（キーボードフックの中でファイルに
  書かないようにするため）。
- **入力モード表示スレッド**: IME 状態の監視（100ms ごと）と表示ウィンドウを受け持ち、
  独自のメッセージループを回します。キーボードフックとは別スレッドなので、
  `Ctrl+B` のリマップには影響しません。
- **キー割り当ての実行スレッド**: フックが捕まえたキー割り当ての動作を実行します。フックの中で
  時間のかかること（プログラムを開く・クリップボードを読み書きする）をすると Windows がフックを
  外してしまうことがあるため、別のスレッドで行います。
- **設定画面スレッド**: 設定画面（とキー割り当て画面）を開いている間だけ動き、独自のメッセージループを回します。
  保存した内容はチャネルでメインスレッドへ送り、メインスレッドがフック・入力モード表示・
  トレイメニューへ反映します。
- 終了時はフックスレッドと入力モード表示スレッドへ `WM_QUIT` を送ってループを抜け、
  フックの解除と表示ウィンドウの破棄を確実に行います。設定画面が開いていれば、保存せずに閉じます。

### 自分が送出したキーの除外

リマップで送る入力には `dwExtraInfo` に固有の署名を付け、フック側で
（`LLKHF_INJECTED` と併せて）自己入力を確実に無視することで、無限ループを防ぎます。

## 安全性・運用

- 常駐メモリは数 MB 程度。
- 権限昇格は不要（`asInvoker` マニフェスト）。
- 終了時にフックを解除し、リソースリークを起こしません。
- 動作の記録は既定で OFF です。ON にしても、入力した文字は記録しません。
- 他ソフトとのキー競合は仕様外です。
