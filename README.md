# アタイの貼り付け

Excel 使用時に **`Ctrl+B` を `Ctrl+Shift+V`（値貼り付け）にリマップ**する、Windows 常駐アプリです。
Rust 製・単体 EXE（ポータブル）で、通常ユーザー権限で動作します。

> **ダウンロード**: ビルド済みの `Atai-paste.exe` は
> [Releases](https://github.com/Yu5rin/MyPaste/releases) から入手できます。
> 導入と更新の手順は [インストール](#インストール) を参照してください。

## 概要

| 項目 | 内容 |
| --- | --- |
| 目的 | Excel 使用時に `Ctrl+B` → `Ctrl+Shift+V` を送出する |
| 範囲 | フォアグラウンドが Excel（`EXCEL.EXE`）のときのみ有効 |
| 動作環境 | Windows 10 / 11（64bit）。**Excel は Microsoft 365 バージョン 2308（2023年8月）以降が必須**（下記参照） |
| 配布形式 | 単体 EXE（ポータブル） |
| 権限 | 通常ユーザー（権限昇格不要） |

> **重要: Excel のバージョン要件**
> `Ctrl+Shift+V`（値貼り付け）のショートカットは、**Microsoft 365 のバージョン 2308（2023年8月）以降**で
> 追加されたものです。**Excel 2019 / 2021（永続版）や、それより古い Microsoft 365 では割り当てられていません。**
>
> 対応していない Excel でこのアプリを ON にすると、`Ctrl+B` は握りつぶされて `Ctrl+Shift+V` が
> 送出されるものの Excel 側がこれを認識しないため、**太字にする（`Ctrl+B`）ことも値貼り付け（`Ctrl+Shift+V`）
> することもできなくなります**。「`Ctrl+B` が壊れた」ように見えますが、原因はこのアプリによる
> リマップです。該当する Excel をお使いの場合は、トレイメニューでこのアプリを OFF にするか終了してください。

## 機能

- **キーリマップ**: Excel が最前面かつ ON のとき、`Ctrl+B` を握りつぶして `Ctrl+Shift+V` を送出します。押しっぱなしにしても最初の 1 回だけ送出します（オートリピート抑制）。
- **Excel 判定**: フォアグラウンドウィンドウのプロセスイメージ名が `EXCEL.EXE` の場合のみ有効。それ以外では `Ctrl+B` はそのまま通します。
- **ON/OFF 切替**: タスクトレイの右クリックメニュー「Ctrl+B で値貼り付け」から。有効時は先頭に「✔」が付きます。OFF 中はリマップせず素通しします。
- **自動起動設定**: メニュー「自動起動」で、スタートアップフォルダのショートカット（`.lnk`）を作成／削除します。有効時は先頭に「✔」が付きます。
- **アイコン切替**: ON = 黒「B」／OFF = 黒「B」＋赤い禁止マーク。
- **バージョン表示**: トレイメニューの先頭に、現在のバージョン（例: `アタイの貼り付け v1.2.3`）を表示します（選択はできません）。
- **更新の確認と適用**: メニュー「更新を確認」、および**起動のたび**に GitHub の
  最新リリースを調べ、新しい版があれば確認のうえ自動で入れ替えます。詳細は
  [自動更新](#自動更新) を参照してください。
- **終了**: メニュー「終了」から。フックを解除してから終了します（リソースリークなし）。
- **状態保持**: ON/OFF はメモリのみ。終了時にリセット（次回起動時は ON）。
- **ログ**: 開発時のみ実行ファイルと同じフォルダの `log.txt` に出力。本番ビルドでは無効。

## インストール

1. [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) から `Atai-paste.exe` をダウンロードします。
2. 任意のフォルダに置き、ダブルクリックで起動します。インストーラーは無く、管理者権限も要りません。

`Program Files` 配下など書き込めない場所に置くと、自動更新は行われず、手動での入れ替えを
案内します（[自動更新](#自動更新) を参照）。

> **SmartScreen の警告について**: 実行ファイルはコード署名していないため、初回起動時に
> Windows SmartScreen の警告が出る場合があります。「詳細情報」→「実行」で起動できます。

### 更新方法

- **アプリ内で更新する**: トレイメニューの「更新を確認」、または起動時の確認で新しい版が
  見つかると、確認のダイアログが出ます。「はい」を選ぶと実行ファイルを入れ替え、新しい版を
  起動します。仕組みは [自動更新](#自動更新) を参照してください。
- **手動で更新する**: トレイメニューの「終了」でアプリを終了してから、
  [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) の新しい `Atai-paste.exe` で
  元のファイルを上書きします。同じ場所に置けば、自動起動の設定もそのまま使えます。

更新後もアイコンが以前のまま表示される場合は、Windows のアイコンキャッシュが原因です。
`ie4uinit.exe -show` を実行するか、サインインし直してください。

## 使い方

1. `Atai-paste.exe` を任意のフォルダに置いて起動します（インストール不要）。
2. タスクトレイに「B」アイコンが表示されます（起動時は ON）。
3. Excel を最前面にして `Ctrl+B` を押すと、`Ctrl+Shift+V`（値貼り付け）が送出されます。
4. 一時的に無効化したいときは、トレイアイコンを右クリック →「Ctrl+B で値貼り付け」。
5. ログオン時に自動起動させたいときは、右クリック →「自動起動」。
6. 終了は右クリック →「終了」。

> **メモ（左クリックについて）**: 仕様では「左クリックで ON/OFF トグル」を想定していますが、
> 採用している `tray-item` クレートは左クリック専用のハンドラを公開していません。
> そのため ON/OFF 切替は右クリックメニューの「Ctrl+B で値貼り付け」に集約しています。

## 自動更新

新しいバージョンが公開されたら、アプリ内から更新できます。

### 通信するタイミング

このアプリが外部と通信するのは、**次の 2 つの場合だけ**です。それ以外では一切通信しません。

| きっかけ | 内容 |
| --- | --- |
| メニュー「更新を確認」を押したとき | 最新リリースを問い合わせる |
| 起動時（**毎回**） | 起動のたびに最新リリースを問い合わせる |

通信は必ず別スレッドで行うため、起動やキー操作を妨げません。失敗しても
「確認できなかった」で済ませ、アプリの動作には影響しません。

タイムアウトも明示しています。確認（Atom / API とも）は **15 秒**、
更新ファイルのダウンロードは **10 分**で打ち切ります。

### 通信先と GitHub API のレート制限対策

GitHub の Releases API（`https://api.github.com/...`）には未認証の場合
**1 時間 60 回**という上限があり、これは端末ごとではなく **IP アドレスごと**に
数えられます。会社などの共有回線では他の通信で先に使い切られてしまい、
更新確認のたびに HTTP 403 が返ることがあります。

`https://github.com/{owner}/{repo}/releases.atom`（Atom フィード）はこの上限とは
**別枠**であるため、このアプリは次の順で確認します。

1. まず Atom フィードで最新のタグだけを確認する。ここで「最新である」と
   分かれば、API は呼ばずに終える（レート制限を消費しない）。
2. Atom で**新しい版が見つかったときだけ**、添付ファイルの詳細
   （ダウンロード URL・SHA256）を取りに API を呼ぶ。呼ぶ頻度が
   「更新があったとき」だけになるので、上限に当たる見込みはほぼ無くなる。
3. その API が失敗しても（403 を含む）、Atom で新しい版があると分かって
   いれば、ダウンロード URL は規則から組み立てて更新を続行する
   （`https://github.com/{owner}/{repo}/releases/download/{tag}/{asset_name}`）。
   **引き換えに SHA256 は分からない**ため、その場合だけ検証を省略します
   （下記「SHA256 の検証について」を参照）。

| 用途 | URL |
| --- | --- |
| 更新の確認（優先） | `https://github.com/Yu5rin/MyPaste/releases.atom` |
| 更新の確認（詳細・新しい版があるときのみ） | `https://api.github.com/repos/Yu5rin/MyPaste/releases/latest` |
| 更新の取得 | 上記いずれかの応答から得られる `https://github.com/...` のダウンロード URL |

更新ファイルの取得先は、応答をそのまま信用せず
**`github.com` / `api.github.com` / `objects.githubusercontent.com` /
`*.githubusercontent.com`（すべて HTTPS）に限定**しています。EXE を取得して
そのまま実行する処理のため、想定外のホストが混入しても取得自体を行いません。

**通信先は `settings.json` に書かれており、利用者が確認・変更できます。**
起動時に自動生成されるので、内容を見れば「どこへ通信するのか」が分かります。
Atom フィードの URL は `api_url` から自動的に組み立てます。`api_url` の
ホストが `api.github.com` でない場合（配布元を差し替えている場合など）は
Atom による確認をせず、従来どおり API だけで確認します。

```jsonc
{
  "update": {
    "check_on_startup": true,   // false にすると起動時の確認をやめ、手動のみになる
    "check_interval_hours": 0,  // 0 は起動のたびに確認。24 にすると 1 日 1 回までになる
    "api_url": "https://api.github.com/repos/Yu5rin/MyPaste/releases/latest",
    "releases_page": "https://github.com/Yu5rin/MyPaste/releases/latest",
    "asset_name": "Atai-paste.exe"
  }
}
```

`settings.json` と `update_state.json`（前回の確認時刻）は実行ファイルと同じフォルダに
置かれます。`Program Files` 配下など書き込めない場所にある場合は
`%LOCALAPPDATA%\Atai-paste` に切り替わります。

### 更新の流れ

1. 上記の順（Atom → 必要なら API）で最新の `tag_name` を取得し、現在の
   バージョンと**数値として**比較します（文字列比較では `1.0.10` < `1.0.9`
   と誤判定するため）。
2. 新しい版があれば、確認のダイアログを表示します。
3. 「はい」を選ぶと実行ファイルをダウンロードします。SHA256 が分かって
   いれば検証します（下記参照）。進捗はトレイアイコンのツールチップに
   表示されます。
4. 検証を通った（または省略した）ら実行ファイルを入れ替え、新しい版を
   起動して自分は終了します。

ダウンロードした一時ファイルは、**入れ替えの成否にかかわらず削除**します。
書き出しが途中で失敗した場合も中途半端なファイルを残しません。強制終了などで
万一残った場合に備えて、起動時に一時フォルダの古い残骸（1 時間以上前のもの）も
掃除します。削除対象は `Atai-paste-<バージョン>.exe` という名前のものだけで、
本体の実行ファイルや無関係なファイルには触れません。

### SHA256 の検証について

**「必ず SHA256 で検証する」わけではありません。** GitHub Releases API から
添付ファイルの `digest`（`sha256:...`）を取得できたときだけ、ダウンロードした
ファイルと突き合わせて検証します。

API が使えなかった場合（前述のレート制限で 403 になった場合など）は、
Atom フィードで分かった新しい版のダウンロード URL を規則から組み立てて
更新を続行しますが、この経路では **SHA256 は分からないため検証を省略**します。
その旨はログに残します。

検証を省略しても、通信自体は HTTPS（Windows 標準の WinHTTP、証明書の検証は
OS に任せる）で行っているため、**そこで防げるのは転送中の破損まで**です。
改ざんそのものへの防御ではない点にご留意ください（ダウンロード元のホストは
前述のとおり GitHub のリリース配信ホストに限定しており、また先頭 2 バイトが
`MZ` であることの最低限の妥当性検査は省略時も行います）。

### 実行中の EXE を入れ替える仕組み

実行中の EXE は Windows がロックしているため上書きできませんが、**リネームはできます**。
そこで次の順で入れ替えます。

1. 新しい実行ファイルを、同じフォルダに `Atai-paste.exe.new` としてコピーで書き出す
2. `Atai-paste.exe` → `Atai-paste.exe.old` にリネーム
3. `Atai-paste.exe.new` → `Atai-paste.exe` にリネーム
4. 新しい EXE を起動して、自分は終了
5. 次回起動時に `.old` を削除

時間のかかる「コピー」を 1 で先に済ませておき、実際の入れ替え（2→3）は
リネーム 2 回だけで行います。リネームは同一ボリューム上ならほぼ一瞬で終わるため、
実行ファイルが存在しない瞬間はごく短くなります。

**保証されること**: 3 のリネームが失敗したことを検知できた場合は 2 を巻き戻すため、
アプリのプロセスが動き続けている限り壊れた状態にはなりません。

**保証されないこと**: 電源断や強制終了など、**OS ごと落ちるケース**では巻き戻しの
コード自体が実行されないため、上記の保証は成立しません。この窓（2 と 3 の間）で
中断されると、`Atai-paste.exe` が存在せず `.old` と `.new` だけが残った状態になり得ます。
このケースに備え、**次回起動時に `.exe` が無く `.old` だけが残っていることを検知したら、
`.old` を `.exe` に戻す（復元を試みる）**ようにしています（`update::cleanup_old`）。
ただし、複製元の `.old` 自体が壊れていた場合など、これでも救えないケースは残ります。

また `Program Files` 配下など書き込めない場所では自動更新を行わず、
リリースページを開いて手動での入れ替えを案内します。

終了処理（トレイメニューの「終了」）は、更新の入れ替え中であれば完了を
（最大 60 秒まで）待ってから行います。これにより、通常の操作で入れ替えの
途中にプロセスが終了することはありません。

## ビルド

Windows（MSVC ツールチェーン推奨）で以下を実行します。

```powershell
# 開発ビルド（コンソール表示あり・log.txt 出力あり）
cargo build

# 本番ビルド（コンソール非表示・ログ無効・サイズ最適化）
cargo build --release
```

生成物: `target/release/Atai-paste.exe`（単体で配布可能）。

### ビルドに関する補足

- アイコン（`src/icons/*.ico`）とマニフェスト（`app.manifest`）は、`build.rs` から
  [`embed-resource`](https://crates.io/crates/embed-resource) 経由で `app.rc` を
  コンパイルし、EXE に埋め込みます。MSVC 環境では Windows SDK の `rc.exe` が使われます。
- 開発中にログを有効化したい本番ビルドでは、`--features devlog` を付けます。
  （通常の本番リリースビルドではログは完全に無効です。）

```powershell
cargo build --release --features devlog
```

### GitHub Actions（手動実行のみ）

`.github/workflows/` の CI / Release ワークフローは自動実行せず、**Actions タブから手動実行**する設定（`workflow_dispatch`）です。

- **CI**: 手動実行すると `clippy` + リリースビルドを行い、`Atai-paste.exe` を Artifact として保存します。
- **Release**: タグ（例 `v1.0.0`）を入力して手動実行すると、EXE をビルドし、`RELEASE_NOTES.md`（変更点）に
  ダウンロードの表（ファイル・サイズ・SHA256）と README への案内を足した本文で、タグと同じ名前の GitHub Release を作成・添付します。

> ローカルに Windows 環境がある場合は、これらを使わず `cargo build --release` で直接ビルドできます。

## モジュール構成

```
src/
 ├ main.rs          // エントリーポイント・スレッド構成・メインループ
 ├ keyboard.rs      // 低レベルキーボードフック（WH_KEYBOARD_LL）
 ├ sendinput.rs     // Ctrl+Shift+V 送出（SendInput）
 ├ excel_check.rs   // Excel 判定（フォアグラウンドプロセス名）
 ├ tray.rs          // タスクトレイ制御（tray-item）
 ├ startup.rs       // 自動起動設定（スタートアップの .lnk 作成／削除）
 ├ update.rs        // 更新の確認・ダウンロード・適用
 ├ update_logic.rs  // 更新確認の判断ロジック（Win32 非依存。Linux でも cargo test 可）
 ├ http.rs          // HTTPS 通信（WinHTTP）
 ├ config.rs        // 設定（settings.json）と確認時刻の記録
 ├ log.rs           // 開発時ログ出力
 └ icons/           // ON/OFF アイコン素材
```

## 技術仕様

| 項目 | 内容 |
| --- | --- |
| 言語 | Rust（edition 2021） |
| フック | `WH_KEYBOARD_LL`（低レベルキーボードフック） |
| キー送出 | `SendInput` API |
| Excel 判定 | `GetForegroundWindow` + `GetWindowThreadProcessId` + `OpenProcess` + `QueryFullProcessImageNameW` |
| タスクトレイ | `tray-item` クレート |
| 自動起動 | スタートアップフォルダの `.lnk`（`IShellLinkW` / `IPersistFile`） |
| HTTPS 通信 | Windows 標準の **WinHTTP**（証明書の検証は OS に任せる） |
| 更新の検証 | SHA256（`sha2` クレート）。API から取得できないときは省略（上記「SHA256 の検証について」参照） |
| ログ | ファイル出力（`log.txt`、開発時のみ） |

通信に WinHTTP を使っているのは、証明書ストアを自前で抱えずに済み、
C やアセンブリのビルドを伴う TLS クレート（rustls / OpenSSL 系）を避けられるためです。
システムのプロキシ設定にも自動で従います。

### スレッド構成

- **フックスレッド**: `WH_KEYBOARD_LL` を設置し、メッセージループを回します。
  低レベルフックのコールバック配信にはメッセージループが必須です。
- **メインスレッド**: タスクトレイ（`tray-item`）を保持し、メニュー操作をチャネル経由で
  受け取ってアイコン切替・自動起動切替・終了処理を行います。`tray-item` は内部で
  独自のメッセージループを持つため、メインスレッドはチャネル受信に専念できます。
- 終了時はフックスレッドへ `WM_QUIT` を送ってループを抜け、フックを確実に解除します。

### 自分が送出したキーの除外

リマップで送る入力には `dwExtraInfo` に固有の署名を付け、フック側で
（`LLKHF_INJECTED` と併せて）自己入力を確実に無視することで、無限ループを防ぎます。

## 安全性・運用

- 常駐メモリは数 MB 程度。
- 権限昇格は不要（`asInvoker` マニフェスト）。
- 終了時にフックを解除し、リソースリークを起こしません。
- ログは開発時のみ出力。本番ビルドでは無効化されます。
- 他ソフトとのキー競合は仕様外です。
