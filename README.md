# アタイの貼り付け

Excel 使用時に **`Ctrl+B` を `Ctrl+Shift+V`（値貼り付け）にリマップ**する、Windows 常駐アプリです。
キーの組み合わせと対象アプリは、[設定画面](#設定画面) で変えられます。
さらに、[キー割り当て](#キー割り当て) で「このキーを押したら、この動作」を自由に追加できます
（キーを送る・定型文を入力する・プログラムを開く・書式なしで貼り付け・文字を整えて貼り付け・
クリップボードの履歴から貼り付け・ウィンドウを常に手前に表示 など）。
Rust 製・単体 EXE（ポータブル）で、通常ユーザー権限で動作します。

> **ダウンロード**: ビルド済みの `Atai-paste.exe` は
> [Releases](https://github.com/Yu5rin/MyPaste/releases) から入手できます。
> 導入と更新の手順は [インストール](#インストール) を参照してください。

## 概要

| 項目 | 内容 |
| --- | --- |
| 目的 | Excel 使用時に `Ctrl+B` → `Ctrl+Shift+V` を送出する（キーは設定画面で変更可） |
| 範囲 | フォアグラウンドが Excel（`EXCEL.EXE`）のときのみ有効（対象アプリは設定画面で追加可） |
| 動作環境 | Windows 10 / 11（64bit）。**Excel は Microsoft 365 バージョン 2308（2023年8月）以降が必須**（下記参照） |
| 配布形式 | 単体 EXE（ポータブル） |
| 権限 | 通常ユーザー（権限昇格不要） |

> **重要: Excel のバージョン要件**
> `Ctrl+Shift+V`（値貼り付け）のショートカットは、**Microsoft 365 のバージョン 2308（2023年8月）以降**で
> 追加されたものです。**Excel 2019 / 2021（永続版）や、それより古い Microsoft 365 では割り当てられていません。**
>
> 対応していない Excel でこのアプリを ON にすると、`Ctrl+B` は握りつぶされて `Ctrl+Shift+V` が
> 送出されるものの Excel 側がこれを認識しないため、**太字にする（`Ctrl+B`）ことも値貼り付け（`Ctrl+Shift+V`）
> することもできなくなります**。「`Ctrl+B` が壊れた」ように見えますが、原因はこのアプリによる
> リマップです。該当する Excel をお使いの場合は、トレイメニューでこのアプリを OFF にするか終了してください。

## 機能

- **キーリマップ**: Excel が最前面かつ ON のとき、`Ctrl+B` を握りつぶして `Ctrl+Shift+V` を送出します。押しっぱなしにしても最初の 1 回だけ送出します（オートリピート抑制）。
  `Ctrl+B` 以外のキーの組み合わせにも変えられます（[設定画面](#設定画面)）。
- **対象アプリの判定**: フォアグラウンドウィンドウのプロセスイメージ名が対象アプリ（既定は `EXCEL.EXE`）の場合のみ有効。それ以外ではキーはそのまま通します。
- **ON/OFF 切替**: タスクトレイの右クリックメニュー「Ctrl+B で値貼り付け」から（キーを変えると、その組み合わせの表示になります）。有効時は先頭に「✔」が付きます。OFF 中はリマップせず素通しします。
- **設定画面**: メニュー「設定...」から、キーの組み合わせ・対象アプリ・入力モード表示・クリップボードの履歴・自動起動・起動時の更新確認を変えられます。保存するとすぐに反映されます（再起動は不要）。設定はまとめて書き出し・読み込みできます。
- **キー割り当て**: メニュー「キー割り当て...」から、好きなキーの組み合わせに動作を割り当てられます
  （AutoHotkey や PowerToys のキーボードマネージャーのような使い方）。動作は「キーを送る」
  「文字を入力する」「プログラムやファイル・URL を開く」「書式なしで貼り付け」「文字を整えて貼り付け」
  「クリップボードの履歴から貼り付け」「前面のウィンドウを常に手前に表示」「キー割り当ての一覧を表示」
  「何もしない（キーを無効にする）」の 9 種類。アプリごとに効かせることもできます。
  割り当てはファイルに書き出して、ほかの PC で読み込めます。メニュー「キー割り当ての一覧」で、
  いま使えるキーを一覧で確かめられます。詳細は [キー割り当て](#キー割り当て) を参照してください。
- **クリップボードの履歴**: コピーした文字を最大 100 件覚えておき、`Ctrl` の 2 回押しやキーの
  組み合わせで一覧を出して貼り付けられます。終了しても暗号化して残せます。同じものは重複しません。
  詳細は [クリップボードの履歴](#クリップボードの履歴) を参照してください。
- **設定の引っ越し**: 設定とキー割り当てを 1 つのファイルに書き出し、新しい PC で読み込めます
  （[設定の引っ越し](#設定の引っ越し)）。
- **自動起動設定**: メニュー「自動起動」で、スタートアップフォルダのショートカット（`.lnk`）を作成／削除します。有効時は先頭に「✔」が付きます。
- **入力モードの表示**: IME の入力モード（`あ` / `A` / `カ` / `ｶ` / `Ａ`）を切り替えた
  瞬間に、画面に大きく表示し、すぐ消します。表示位置（画面中央・マウスの近く・入力位置の近く）、
  色、時間、大きさ、不透明度を変えられます。メニュー「入力モードを表示」で
  ON/OFF でき（有効時は先頭に「✔」）、状態は `settings.json` に保存されます。
  詳細は [入力モードの表示](#入力モードの表示) を参照してください。
- **アイコン切替**: ON = 黒「B」／OFF = 黒「B」＋赤い禁止マーク。
- **バージョン表示**: トレイメニューの先頭に、現在のバージョン（例: `アタイの貼り付け v1.5.1`）を表示します（選択はできません）。
- **更新の確認と適用**: メニュー「更新を確認」、および**起動のたび**に GitHub の
  最新リリースを調べ、新しい版があれば確認のうえ自動で入れ替えます。詳細は
  [自動更新](#自動更新) を参照してください。
- **二重起動の防止**: すでに起動しているときにもう一度起動しても、何も表示せずに終わります
  （起動しているものはトレイにあります）。
- **終了**: メニュー「終了」から。フックを解除してから終了します（リソースリークなし）。
- **状態保持**: 「Ctrl+B で値貼り付け」と「キー割り当てを使う」の ON/OFF はメモリのみ。終了時にリセット（次回起動時は ON）。
- **動作の記録（トラブル調査用）**: 設定画面で ON にすると、`log.txt` に動作を記録します（既定は OFF）。
  詳細は [動作の記録](#動作の記録トラブル調査用) を参照してください。

## インストール

1. [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) から `Atai-paste.exe` をダウンロードします。
2. 任意のフォルダに置き、ダブルクリックで起動します。インストーラーは無く、管理者権限も要りません。

`Program Files` 配下など書き込めない場所に置くと、自動更新は行われず、手動での入れ替えを
案内します（[自動更新](#自動更新) を参照）。

> **SmartScreen の警告について**: 実行ファイルはコード署名していないため、初回起動時に
> Windows SmartScreen の警告が出る場合があります。「詳細情報」→「実行」で起動できます。

### 更新方法

- **アプリ内で更新する**: トレイメニューの「更新を確認」、または起動時の確認で新しい版が
  見つかると、確認のダイアログが出ます。「はい」を選ぶと実行ファイルを入れ替え、新しい版を
  起動します。仕組みは [自動更新](#自動更新) を参照してください。
- **手動で更新する**: トレイメニューの「終了」でアプリを終了してから、
  [Releases](https://github.com/Yu5rin/MyPaste/releases/latest) の新しい `Atai-paste.exe` で
  元のファイルを上書きします。同じ場所に置けば、自動起動の設定もそのまま使えます。

更新後もアイコンが以前のまま表示される場合は、Windows のアイコンキャッシュが原因です。
`ie4uinit.exe -show` を実行するか、サインインし直してください。

## 使い方

1. `Atai-paste.exe` を任意のフォルダに置いて起動します（インストール不要）。
2. タスクトレイに「B」アイコンが表示されます（起動時は ON）。
3. Excel を最前面にして `Ctrl+B` を押すと、`Ctrl+Shift+V`（値貼り付け）が送出されます。
   キーや対象アプリを変えたいときは、右クリック →「設定...」。
   ほかのキーに動作を割り当てたいときは、右クリック →「キー割り当て...」。
4. 一時的に無効化したいときは、トレイアイコンを右クリック →「Ctrl+B で値貼り付け」。
5. ログオン時に自動起動させたいときは、右クリック →「自動起動」。
   入力モードの表示を止めたいときは、右クリック →「入力モードを表示」。
   キー割り当てを一時的に止めたいときは、右クリック →「キー割り当てを使う」。
6. 終了は右クリック →「終了」。

> **メモ（左クリックについて）**: 仕様では「左クリックで ON/OFF トグル」を想定していますが、
> 採用している `tray-item` クレートは左クリック専用のハンドラを公開していません。
> そのため ON/OFF 切替は右クリックメニューの「Ctrl+B で値貼り付け」に集約しています。

## 設定画面

トレイアイコンを右クリック →「設定...」で開きます。「保存」を押すと `settings.json` に書き込み、
**その場で反映**します（アプリの再起動は要りません）。「キャンセル」または `Esc` で、変更せずに閉じます。

| 項目 | 内容 |
| --- | --- |
| キーの組み合わせ | `Ctrl` / `Shift` / `Alt` と、キー（`A`〜`Z`、`0`〜`9`、`F1`〜`F12`）の組み合わせ。既定は `Ctrl+B` |
| 対象アプリ | リマップするアプリのプロセス名。1 行に 1 つ（空白・カンマ区切りでも可）。既定は `EXCEL.EXE` |
| 入力モードの表示 | ON/OFF、表示位置、色、表示時間（0.1〜5 秒）、フェードアウトの時間（0〜2 秒）、大きさ（40〜600 px）、不透明度（30〜100 %）、全画面のアプリでは表示しない。時間は秒で入力し、`1.5` のような小数も使えます。「プレビュー」で試しに表示できます |
| クリップボードの履歴 | ON/OFF、一覧を出す操作、覚えておく件数、一覧を出す位置・幅・不透明度・1 ページの件数・配色、終了後も残すか、「履歴を消す」（[クリップボードの履歴](#クリップボードの履歴) を参照） |
| 起動・更新・記録 | Windows にサインインしたら自動で起動する、起動時に新しいバージョンを確認する、トラブル調査用に動作を記録する（「記録を開く」で `log.txt` を開けます） |

そのほかのボタン:

- **設定ファイルの場所を開く**: `settings.json` を選んだ状態でエクスプローラーを開きます。
- **既定に戻す**: 画面の値を既定値にします（「保存」を押すまでは反映しません）。
  自動起動は既定値を持たないため、今の選択のままにします。
- **設定を書き出す... / 設定を読み込む...**: 下記の [設定の引っ越し](#設定の引っ越し) を参照してください。

### 設定の引っ越し

新しい PC へ移るときは、古い PC で「設定...」→「設定を書き出す...」を押し、できたファイル
（既定の名前は `アタイの貼り付けの設定.json`）を新しい PC へ持っていきます。新しい PC では、
`Atai-paste.exe` を置いて起動し、「設定...」→「設定を読み込む...」でそのファイルを選びます。

- 含まれるもの: 値貼り付けのキーと対象アプリ、入力モードの表示、クリップボードの履歴の設定、
  キー割り当てと定型文のすべて、記録・更新確認の設定、自動起動の状態。`settings.json` に手で書いた項目も含みます。
- 含まれないもの: クリップボードの履歴の中身（暗号化しているため、ほかの PC では読めません）。
- 読み込むと、今の設定とキー割り当てを**置き換えて**、すぐに使い始めます（再起動は要りません）。
- 書き出すのは**保存済み**の設定です。画面で変えたばかりの値は、先に「保存」してから書き出してください。
- キー割り当てだけを移したり、今の割り当てに足したりするときは、キー割り当て画面の
  「書き出す...」「読み込む...」を使います。

## クリップボードの履歴

コピーした文字を覚えておき、あとから一覧で選んで貼り付けられます（Clibor や Ditto のような使い方です）。
「設定...」の「クリップボードの履歴」で、「コピーした文字を記録して、一覧から選んで貼り付ける」を
ON にして保存すると使えます（既定は OFF）。

一覧を出す操作をすると、入力位置（またはマウス）の近くに、タイトルバーの無い、1 ピクセルの枠だけの
細長い半透明の画面が出ます（Clibor のメイン画面のような形です）。

```
┌─────────────────┐
│ 履歴 │ 定型文 │     1〜20 / 1000 │ ← タブ（左右の矢印キーかクリックで切り替え）
│  1 見積書 2026年度 第…          │
│  2 東京都千代田区丸の内         │   ┌────────────┐
│  3 よろしくお願い…        3行  │ → │選んだものの全文    │
│  …                              │   │（1 行に収まらないとき）│
│ 20 …                            │   └────────────┘
└─────────────────┘
```

- **タブ**: 「履歴」（コピーしたもの）と「定型文」（登録しておいた文）。左右の矢印キーか、タブの
  クリックで切り替えます。履歴が空で定型文があるときは、定型文のタブから始まります。
- **一覧**: 1 ページに決めた件数（既定 20 件）。1 行に 1 件、番号・最初の行（定型文は名前）・行数
  （2 行以上のとき）を出し、1 行おきに色を変えています。
- **全文の吹き出し**: 選んでいるものが 1 行に収まらない（複数行か、途中で切れている）とき、定型文は
  いつも、選んだ行の横に全文を出します（長いものは 20 行まで）。
- **選び方**: マウスを乗せると選ばれ、クリックで貼り付けます。キーボードでは上下の矢印キーで選び、
  `Enter` で貼り付けます。`Home` / `End` でページの最初・最後へ移ります。
- **ページ**: `PageUp` / `PageDown`、マウスのホイールで前後のページへ移ります。
- **右クリックのメニュー**（またはアプリケーションキー・`Shift+F10`）: 貼り付け、定型文に登録
  （履歴のとき）、この履歴を消す、定型文の編集...、閉じる。
- **半透明**: 不透明度は設定画面で決めます（既定 90%）。一覧の上で `Shift` を押しながらホイールを
  回しても変えられ（奥に回すと濃く、手前に回すと薄く）、変えた値は次からも使います。
- **配色**: 設定画面で「Windows の色」「ライト」「ダーク」「ブルー」「グリーン」から選べます
  （全文の吹き出しも同じ配色になります）。
- **閉じる**: `Esc`、またはほかの場所をクリックすると、何もせずに閉じます。
- **1 件を消す**: 履歴を選んで `Delete` を押すと、その 1 件を消します
  （間違えてコピーしたパスワードなどを消すときに）。
- 画面の幅（既定 260 ピクセル。200〜600）と 1 ページの件数（10〜40）は、設定画面で変えられます。

- **貼り付け方**: 選んだものを書式なしで貼り付けます。貼り付けたあと、クリップボードは元の内容に戻ります。
- **重複しない**: すでに履歴にある文字をもう一度コピーすると、前のものを消していちばん上に移します。
- **覚えておく件数**: 10〜10,000 件（既定は 1,000 件）。超えると古いものから消えます。
  大きなものばかりをたくさん覚えてメモリや保存するファイルが大きくなりすぎないよう、履歴全体が
  32 MB を超えたときも古いものから消します（1 件は 5 万文字まで）。
- **終了しても残す**（既定は ON）: 履歴をファイル（`settings.json` と同じ場所の `clip_history.dat`）に
  保存し、次に起動したときに続きから使えます。ファイルは Windows の機能（DPAPI）で暗号化しており、
  **この PC の同じユーザーでなければ読めません**。OFF にすると、保存していたファイルを消し、
  履歴はアプリを終了すると消えるようになります。記録そのものを OFF にしたときも、ファイルを消します。
- **履歴を消す**: 設定画面の「履歴を消す」で、保存したものも含めてすべて消します。
- 記録するのは文字だけです（画像やファイルは記録しません）。パスワード管理ソフトなどが
  「記録しないで」と印を付けた内容（Windows のクリップボードの履歴に残らないもの）は記録しません。
  1 件が 5 万文字を超えるものも記録しません。

一覧を出す操作は、次から選べます。

| 一覧を出す操作 | 内容 |
| --- | --- |
| キーの組み合わせ（既定） | `Ctrl` / `Shift` / `Alt` / `Win` とキーの組み合わせ。既定は `Ctrl+Alt+H` |
| Ctrl を素早く 2 回押す | `Ctrl` だけを 2 回、決めた間隔（既定 0.4 秒、0.2〜1 秒）の中で押して離す |
| Shift を素早く 2 回押す | 同じく `Shift` |
| Alt を素早く 2 回押す | 同じく `Alt` |

- 2 回押しは、そのキーだけを短く押したときに数えます（`Ctrl+C` のようにほかのキーと組み合わせた押し方や、
  長押しは数えません）。キーそのものはアプリにもそのまま届きます。
- 一覧を出す位置は「入力位置の近く」（分からないアプリではマウスの近く）か「マウスの近く」です。
- 一覧を出すキーは、「キー割り当てを使う」を OFF にしていても効きます。値貼り付けのキーや
  キー割り当てと同じキーにはできません（保存するときに知らせます）。
- キー割り当ての動作「クリップボードの履歴から貼り付け」でも、同じ一覧を出せます
  （別のキーでも出したいとき）。件数などは上の設定に従います。
- Windows 標準のクリップボードの履歴（`Win+V`）とは別のものです。

`settings.json` では次のように書きます。

```jsonc
{
  "clipboard_history": {
    "enabled": true,
    "trigger": "double_ctrl",   // "hotkey" / "double_ctrl" / "double_shift" / "double_alt"
    "hotkey": "Ctrl+Alt+H",     // trigger が "hotkey" のとき
    "double_tap_ms": 400,       // 2 回押しの間隔（200〜1000 ミリ秒）
    "max_items": 1000,          // 10〜10000
    "keep_after_exit": true,
    "position": "caret",        // "caret"（入力位置の近く）/ "mouse"
    "width": 260,               // 一覧の幅（200〜600。96 DPI 基準のピクセル）
    "opacity": 90,              // 不透明度（30〜100 %）
    "page_size": 20,            // 1 ページの件数（10〜40）
    "theme": "system"           // "system" / "light" / "dark" / "blue" / "green"
  }
}
```

### キーの組み合わせの決まり

- 英字・数字のキーには `Ctrl` か `Alt` を組み合わせてください。単独や `Shift` だけでは、
  普段の文字入力ができなくなるため保存できません。`F1`〜`F12` は単独でも使えます。
- `Ctrl+Shift+V` は値貼り付けそのものなので登録できません。
- 押されている修飾キーが**ちょうど一致したときだけ**反応します（`Ctrl+B` の設定で
  `Ctrl+Shift+B` を押しても反応しません。`Win` キーを押しているときも反応しません）。
- `Alt` を含む組み合わせでは、アプリのメニュー（Excel ではリボンのキー操作）が開かないよう、
  `Alt` を離す操作の前に、何も割り当てられていないキー（仮想キー `0xE8`）を 1 回送ります。
- その組み合わせがもともと持っていた機能（例: `Ctrl+Q`）は、対象アプリの中では使えなくなります。

### 対象アプリの書き方

- プロセス名は、タスクマネージャーの「詳細」タブの「名前」の列で確かめられます。
- 大文字・小文字は区別しません。`.exe` は省略でき、フォルダ付きで書いてもファイル名だけを使います。
- 名前に空白を含む場合は `"My App.exe"` のように `"` で囲んでください。

### settings.json での設定

設定画面の内容は `settings.json` に次のように保存されます（他の項目はそのまま残します）。
直接編集した場合は、アプリを再起動すると反映されます。使えないキーが書かれていた場合は
`Ctrl+B` で動き、対象アプリが空の場合は `EXCEL.EXE` で動きます。

```jsonc
{
  "remap": {
    "hotkey": "Ctrl+B",              // 例: "Ctrl+Shift+B"、"Alt+Q"、"F12"
    "target_apps": ["EXCEL.EXE"]
  }
}
```

## 定型文

よく使う文（あいさつ・住所・口座番号など）を登録しておき、クリップボードの履歴の一覧の「定型文」タブ
から選んで貼り付けられます。

- **登録・編集**: トレイメニューの「定型文...」（または一覧の右クリック「定型文の編集...」）で開く画面で、
  名前と本文を書いて「新しい定型文として追加」、直すときは一覧で選んで「選んだ定型文を更新」、
  最後に「保存」を押します。名前を空にすると、本文の最初の行を一覧に出します。
- **履歴から登録**: 履歴の一覧で右クリック →「定型文に登録」で、その履歴をそのまま定型文に足します
  （同じ本文がすでにあれば足しません）。
- **日付・時刻**: 本文の `{date}` は今日の日付（`2026/10/08`）、`{time}` は今の時刻、`{datetime}` は
  両方に置き換えて貼り付けます。
- **CSV**: 「CSV から読み込む...」「CSV に書き出す...」で、Excel などでまとめて編集できます。
  1 列目が名前、2 列目が本文です（1 行目に「名前,本文」の見出しがあれば飛ばします。1 列だけなら本文
  として読みます）。文字コードは UTF-8（Excel では「CSV UTF-8」で保存）です。
- 最大 1,000 件、1 件の本文は 2 万文字まで。`settings.json` の `snippets` に保存するので、
  [設定の引っ越し](#設定の引っ越し) にも含まれます。
- 定型文のタブは、クリップボードの履歴の一覧の中にあります。設定画面で「コピーした文字を記録して、
  一覧から選んで貼り付ける」を ON にして使ってください。

## キー割り当て

トレイアイコンを右クリック →「キー割り当て...」で開きます。「このキーを押したら、この動作をする」
という割り当てを、何個でも追加できます（AutoHotkey や PowerToys のキーボードマネージャーのような
使い方です）。「保存」を押すと**すぐに使えます**（再起動は要りません）。

```
アタイの貼り付け v1.5.0
─────────────────
✔ Ctrl+B で値貼り付け
✔ キー割り当てを使う        ← 一時的にすべて止めるとき
✔ 自動起動
✔ 入力モードを表示
─────────────────
設定...
キー割り当て...             ← 割り当ての画面
定型文...                   ← 定型文の画面
キー割り当ての一覧          ← いま使えるキーを一覧で表示
更新を確認
─────────────────
終了
```

### 使い方

1. 右側の「割り当ての内容」で、キー・動作・内容・効くアプリを決めます。
2. 「新しい割り当てとして追加」を押すと、左の一覧に加わります。
3. 直したいときは、左の一覧で選んで右側を書き換え、「選んだ割り当てを更新」を押します。
4. 「保存」を押します。保存せずに閉じようとすると、確かめるメッセージが出ます。

一覧は上から順に調べ、最初に当てはまった割り当てだけを使います（「上へ」「下へ」で並べ替えられます）。
同じキーで同じアプリに効く割り当てが 2 つあると、保存するときに知らせます。
一時的に止めたい割り当ては「この割り当てを使う」を外します（一覧に［停止中］と出ます）。

**書き出しと読み込み**: 「書き出す...」で、一覧にある割り当てをファイル（JSON）に保存します。
ほかの PC では「読み込む...」でそのファイルを選び、今の割り当ての後ろに足すか、置き換えるかを選びます。
`settings.json` そのものも読み込めます。読み込んだ割り当ても、「保存」を押すまでは使いません。

**一覧の表示**: トレイメニューの「キー割り当ての一覧」（またはその動作を割り当てたキー）で、値貼り付けの
キーとすべてのキー割り当てを一覧で表示します。どのキーに何を割り当てたか忘れたときに使います。

### 動作の種類

| 動作 | 内容に書くもの | 使い方の例 |
| --- | --- | --- |
| キーを送る | 送るキー。カンマで区切ると順に送る | `F9` → `Ctrl+Alt+V, V, Enter`（「形式を選択して貼り付け」で値だけを貼る。`Ctrl+Shift+V` が無い Excel 2019 / 2021 向けの代わりとして） |
| 文字を入力する | 入力する文字（改行も可） | `Ctrl+Alt+D` → `{date}`（今日の日付を入力） |
| プログラムやファイル・URL を開く | 開くもの（と引数） | `Ctrl+Alt+N` → `notepad.exe` |
| 書式なしで貼り付け | （なし） | `Ctrl+Alt+V` → Web や Word からコピーした文字を、文字だけ貼り付ける |
| 文字を整えて貼り付け | 整え方（チェックで選ぶ） | `Ctrl+Alt+T` → 全角の数字や `▲1,200` を `-1200` にして貼る（下記） |
| クリップボードの履歴から貼り付け | （なし） | `Ctrl+Alt+Y` → 少し前にコピーしたものを選んで貼る（下記） |
| キー割り当ての一覧を表示 | （なし） | `Ctrl+Alt+L` → 割り当てたキーを忘れたときに |
| 前面のウィンドウを常に手前に表示 | （なし） | `Win+Shift+T` → 押すたびに切り替え（画面に「固定」「解除」と出ます） |
| 何もしない（キーを無効にする） | （なし） | `F1`（Excel だけ）→ うっかりヘルプを開かないように |

- **キー**: `Ctrl` / `Shift` / `Alt` / `Win` と、`A`〜`Z`・`0`〜`9`・`F1`〜`F24`・`Space`・`Enter`・`Tab`・
  `Esc`・`Backspace`・`Delete`・`Insert`・`Home`・`End`・`PageUp`・`PageDown`・矢印（`Left` / `Up` /
  `Right` / `Down`）の組み合わせ。`F1`〜`F24` 以外は、`Ctrl`・`Alt`・`Win` のどれかと組み合わせてください
  （単独や `Shift` だけでは、普段の入力ができなくなるため）。
- **文字を入力する**: `{date}` は今日の日付（`2026/10/05`）、`{time}` は今の時刻（`13:45`）、
  `{datetime}` は両方に置き換えます。`{` そのものは `{{`、`}` は `}}` と書きます。IME の状態に
  かかわらず、書いたとおりの文字を入力します。入れ方は 2 通りです。
  - **まとめて貼り付ける**（既定）: クリップボードを使って `Ctrl+V` で一度に貼り付け、そのあと元の
    クリップボードの内容へ戻します。長い文でも一瞬で入り、入力補完などに邪魔されません。
    一時的に入れた文字は、Windows のクリップボードの履歴（`Win+V`）には残しません。
    待っている間に別のものをコピーした場合は、それを消さないよう元に戻しません。
    **貼り付けを受け付けない入力欄では、自動で 1 文字ずつの入力に切り替えます**（下記）。
  - **1 文字ずつ**（「まとめて貼り付ける」を外す）: いつもキーを打ったときと同じように 1 文字ずつ送ります。
  - **貼り付けを受け付けるかの見分け方**: 文字そのものはクリップボードに置かず、「求められたら渡す」
    という予約（遅延レンダリング）だけを置いて `Ctrl+V` を送ります。貼り付け先が 0.5 秒以内に文字を
    読みに来たら渡し、来なければ受け付けない入力欄とみなして、クリップボードを元に戻してから
    1 文字ずつ入力します。予約の段階では文字を渡していないので、二重には入りません。
    ただし、`Ctrl+V` を受け付けない欄が `Ctrl+V` を別の意味に使っている場合（コンソールで `^V` と
    表示されるなど）は、その動きが起きたあとに 1 文字ずつ入力されます。また、クリップボードの中身を
    すぐに読む常駐ソフト（クリップボード管理ソフトなど）を使っていると、受け付けたと見なされることが
    あります（Windows 標準のクリップボードの履歴は読みに来ません）。
  - 貼り付けるので、Excel でセルを選んだだけの状態（編集中でない）に複数行の文を入れると、
    行ごとに下のセルへ分かれて入ります。
- **書式なしで貼り付け**: クリップボードの文字だけを取り出してクリップボードに入れ直し、`Ctrl+V` を
  送ります。そのため、**貼り付けたあとのクリップボードも文字だけになります**。
- **文字を整えて貼り付け**: クリップボードの文字を、チェックした整え方で直してから貼り付けます。
  **クリップボードの中身は変えません**（貼り付けたあと、元の内容に戻ります）。整え方は次の 10 種類で、
  チェックしたものを下の表の順に当てます。

  | 整え方 | 例 |
  | --- | --- |
  | 全角英数・記号を半角に | `ＡＢＣ１２３（株）` → `ABC123(株)`（全角の空白も半角に。`￥` はそのまま） |
  | 半角カタカナを全角に | `ｶﾞｷﾞｸﾞ` → `ガギグ` |
  | ▲ △ (123) をマイナスに | `▲1,200` `△50` `(300)` `（300）` → `-1,200` `-50` `-300` `-300` |
  | 桁区切りの , を除く | `1,234,567` → `1234567`（数字の間の 3 桁区切りだけ。`a,b` はそのまま） |
  | 各行の前後の空白を除く | 行ごとに、先頭と末尾の空白・タブを除く |
  | 空の行を除く | 何も書かれていない行を除く |
  | 続く空白を 1 つに | `A␣␣␣B` → `A␣B`（タブも空白として扱う） |
  | 空白をすべて除く | 空白・全角の空白・タブを除く |
  | 改行を除いて 1 行に | 複数行を 1 行につなげる |
  | 全体の前後の空白を除く | 全体の先頭と末尾の空白・改行を除く |

  例えば「全角英数・記号を半角に」「▲ △ (123) をマイナスに」「桁区切りの , を除く」を選ぶと、
  会計ソフトや PDF からコピーした `△１，２００` が `-1200` になり、Excel で数値として扱えます。
- **クリップボードの履歴から貼り付け**: [クリップボードの履歴](#クリップボードの履歴) の一覧を出します。
  設定画面で一覧を出す操作を決めていても、別のキーでも出したいときに使います。この割り当てがあれば、
  設定画面で記録を OFF にしていても記録します（件数などは設定画面の値に従います）。
- **効くアプリ**: 「すべてのアプリ」か、「下に書いたアプリだけ」（プロセス名を空白で区切って書く。
  例 `EXCEL.EXE WINWORD.EXE`）。
- 値貼り付け（`Ctrl+B`）のキーと同じキーは、値貼り付けが先に効くので使えません（保存するときに知らせます）。

### 注意

- **Windows が先に使うキーは割り当てられません**: `Ctrl+Alt+Delete`、`Win+L` など。
- **管理者として実行しているアプリ**の中では、キー割り当ては効きません（Windows の仕組みで、
  通常の権限のアプリからは操作できないため）。「常に手前に表示」も、そのウィンドウには効きません
  （画面に「不可」と出ます）。
- **そのキーがもともと持っていた機能**は、割り当てが効くアプリの中では使えなくなります。
- `Alt` や `Win` を含むキーでも、離したときにメニューやスタートが開かないようにしています。
- **キーを送る**は、書いたキーを間を空けずに続けて送ります。ダイアログを開くキーのあとに続けて
  操作する場合など、アプリによっては取りこぼすことがあります。

### settings.json での書き方

キー割り当ては `settings.json` の `hotkeys` に保存されます。直接編集した場合は、アプリを再起動すると
反映されます（読めない割り当ては使わず、[動作の記録](#動作の記録トラブル調査用) に理由を残します）。

```jsonc
{
  "hotkeys": [
    { "hotkey": "Ctrl+Alt+V", "action": "paste_plain" },
    { "hotkey": "F9", "action": "send_keys", "value": "Ctrl+Alt+V, V, Enter", "apps": ["EXCEL.EXE"] },
    { "hotkey": "Ctrl+Alt+D", "action": "type_text", "value": "{date}" },
    { "hotkey": "Ctrl+Alt+S", "action": "type_text", "value": "よろしくお願いいたします。", "input": "keys" },
    { "hotkey": "Ctrl+Alt+N", "action": "run", "value": "notepad.exe", "args": "" },
    { "hotkey": "Ctrl+Alt+T", "action": "paste_transform", "value": "zen_to_han,negative_marks,remove_commas" },
    { "hotkey": "Ctrl+Alt+Y", "action": "clipboard_history" },
    { "hotkey": "Ctrl+Alt+L", "action": "show_list" },
    { "hotkey": "Win+Shift+T", "action": "toggle_topmost" },
    { "hotkey": "F1", "action": "block", "apps": ["EXCEL.EXE"], "enabled": false }
  ]
}
```

`action` は `send_keys` / `type_text` / `run` / `paste_plain` / `paste_transform` / `clipboard_history` /
`toggle_topmost` / `show_list` / `block` のどれかです。`paste_transform` の `value` には、整え方を
カンマで区切って書きます（`zen_to_han`（全角英数・記号を半角に）/ `han_kana_to_zen` / `negative_marks` /
`remove_commas` / `trim_lines` / `remove_blank_lines` / `collapse_spaces` / `remove_spaces` /
`join_lines` / `trim`。書いた順にかかわらず、上の表の順に当てます）。
`enabled` を省くと使う（`true`）扱い、`apps` を省くとすべてのアプリです。`input` は「文字を入力する」の
入れ方で、`"paste"`（まとめて貼り付ける。省いたとき）か `"keys"`（1 文字ずつ）です。

## 入力モードの表示

`半角/全角` キーやカタカナへの切り替えなどで IME の入力モードを変えると、画面に
モードを大きく表示します（既定では画面中央に 0.4 秒表示したあと 0.25 秒で消えます。
出し方は [設定画面](#設定画面) で変えられます）。

- **表示する文字**: `あ`（ひらがな）、`カ`（全角カタカナ）、`ｶ`（半角カタカナ）、
  `Ａ`（全角英数）、`A`（半角英数・IME オフ）
- **表示するとき**: 同じウィンドウの中でモードが変わったときだけ。`Alt+Tab` などで
  モードの違うウィンドウへ移っただけでは表示しません。
- **表示する場所**: 次の 3 つから選べます。大きさはモニターの拡大率（DPI）に合わせます。
  - **画面中央**（既定）: 前面ウィンドウがあるモニターの中央（タスクバーを除いた領域）
  - **マウスの近く**: マウスカーソルの右下（画面の端では左や上へずらします）
  - **入力位置の近く**: 文字を入力している位置（キャレット）の右下。ブラウザーなど、
    入力位置を Windows に知らせないアプリでは取れないため、画面中央に表示します
- **色と不透明度**: 「濃い色」（濃いグレーに白い文字。既定）と「明るい色」（明るいグレーに
  濃い文字）から選べます。不透明度は 30〜100 % です（既定 90 %）。
- **全画面のアプリの間は表示しない**: ON にすると、ゲーム・動画の全画面再生・
  プレゼンテーションの間は表示しません（Windows がそう判断している間。既定は OFF）。
- **操作の邪魔をしない**: 表示はクリックを下のウィンドウへ素通しし、フォーカスも奪いません。
  タスクバーにも出ません。
- **状態が取れないとき**: 管理者権限で動いているウィンドウなど、IME の状態を読み取れない
  相手では何も表示しません。

前面ウィンドウの入力欄の IME 状態を 100ms ごとに調べています（`ImmGetDefaultIMEWnd` で
得た IME ウィンドウへ `WM_IME_CONTROL` を `SendMessageTimeoutW` で問い合わせるため、
相手が固まっていても巻き込まれません）。

### 設定

[設定画面](#設定画面) で変えられます。値は `settings.json` の `ime_indicator` に保存され、
メニューで切り替えた ON/OFF もここに保存されます（ファイルの他の内容はそのまま残します）。

```jsonc
{
  "ime_indicator": {
    "enabled": true,   // false で表示しない
    "hold_ms": 400,    // 消え始めるまでの表示時間（ミリ秒。100〜5000）
    "fade_ms": 250,    // フェードアウトにかける時間（ミリ秒。0〜2000。0 ですぐ消す）
    "size": 120,       // 表示の一辺（拡大率 100% のときのピクセル。40〜600）
    "position": "center",  // "center"（画面中央）/ "mouse"（マウスの近く）/ "caret"（入力位置の近く）
    "theme": "dark",   // "dark"（濃い色）/ "light"（明るい色）
    "opacity": 90,     // 不透明度（%。30〜100）
    "hide_in_fullscreen": false  // true で全画面のアプリの間は表示しない
  }
}
```

設定画面で保存した場合はすぐに反映されます。`settings.json` を直接編集した場合は、
アプリを再起動すると反映されます。

### Windows 標準の中央表示との二重表示を避ける

Windows にも同じような「入力モードを画面中央に表示する」機能があり、両方が有効だと
二重に表示されます。こちらを使う場合は、Windows 側を次の手順でオフにしてください。

1. タスクバーの入力モード表示（`あ` や `A`）を右クリックし、「設定」を開く
   （Windows 11 では「設定」→「時刻と言語」→「言語と地域」→ 日本語の「…」→
   「言語のオプション」→ Microsoft IME の「…」→「キーボード オプション」でも開けます）。
2. 「全般」を開く。
3. 「IME 入力モード切替の通知」の「画面中央に表示する」をオフにする。

項目の名前や場所は Windows のバージョンによって少し異なる場合があります。

## 動作の記録（トラブル調査用）

「キーが効かない」「入力モードが表示されない」などのときの調査のために、アプリの動作を
`log.txt` に記録できます。**既定では記録しません。**

1. 設定画面の「トラブル調査用に動作を記録する（log.txt）」を ON にして「保存」します
   （再起動は要りません。その時点の版と設定を最初に記録します）。
2. うまく動かない操作をもう一度行います。
3. 設定画面の「記録を開く」で `log.txt` を開き、内容を確かめます（問い合わせの際に添えてください）。
4. 調べ終わったら OFF に戻します。

記録する内容:

- 起動時の版・実行ファイルと設定ファイルの場所・設定の内容
- 設定したキーを押したときに、値貼り付けを送ったか、送らなかった理由（OFF だった・前面の
  アプリが対象外だった。対象外のときはそのアプリのプロセス名）
- 入力モードを表示したこと、IME の状態を読み取れなくなった・読み取れるようになったこと
- 更新の確認の結果、エラー

**入力した文字は記録しません**（キーボードについて記録するのは、設定したキーの組み合わせを
押したときだけです）。ただし、ファイルの場所（ユーザー名を含むことがあります）は記録します。

`log.txt` は `settings.json` と同じフォルダに置きます。1 MB を超えると `log.old.txt` に
回して新しく作り直すので、大きくなり続けることはありません。

## 自動更新

新しいバージョンが公開されたら、アプリ内から更新できます。

### 通信するタイミング

このアプリが外部と通信するのは、**次の 2 つの場合だけ**です。それ以外では一切通信しません。

| きっかけ | 内容 |
| --- | --- |
| メニュー「更新を確認」を押したとき | 最新リリースを問い合わせる |
| 起動時（**毎回**） | 起動のたびに最新リリースを問い合わせる |

通信は必ず別スレッドで行うため、起動やキー操作を妨げません。失敗しても
「確認できなかった」で済ませ、アプリの動作には影響しません。

タイムアウトも明示しています。確認（Atom / API とも）は **15 秒**、
更新ファイルのダウンロードは **10 分**で打ち切ります。

### 通信先と GitHub API のレート制限対策

GitHub の Releases API（`https://api.github.com/...`）には未認証の場合
**1 時間 60 回**という上限があり、これは端末ごとではなく **IP アドレスごと**に
数えられます。会社などの共有回線では他の通信で先に使い切られてしまい、
更新確認のたびに HTTP 403 が返ることがあります。

`https://github.com/{owner}/{repo}/releases.atom`（Atom フィード）はこの上限とは
**別枠**であるため、このアプリは次の順で確認します。

1. まず Atom フィードで最新のタグだけを確認する。ここで「最新である」と
   分かれば、API は呼ばずに終える（レート制限を消費しない）。
2. Atom で**新しい版が見つかったときだけ**、添付ファイルの詳細
   （ダウンロード URL・SHA256）を取りに API を呼ぶ。呼ぶ頻度が
   「更新があったとき」だけになるので、上限に当たる見込みはほぼ無くなる。
3. その API が失敗しても（403 を含む）、Atom で新しい版があると分かって
   いれば、ダウンロード URL は規則から組み立てて更新を続行する
   （`https://github.com/{owner}/{repo}/releases/download/{tag}/{asset_name}`）。
   **引き換えに SHA256 は分からない**ため、その場合だけ検証を省略します
   （下記「SHA256 の検証について」を参照）。

| 用途 | URL |
| --- | --- |
| 更新の確認（優先） | `https://github.com/Yu5rin/MyPaste/releases.atom` |
| 更新の確認（詳細・新しい版があるときのみ） | `https://api.github.com/repos/Yu5rin/MyPaste/releases/latest` |
| 更新の取得 | 上記いずれかの応答から得られる `https://github.com/...` のダウンロード URL |

更新ファイルの取得先は、応答をそのまま信用せず
**`github.com` / `api.github.com` / `objects.githubusercontent.com` /
`*.githubusercontent.com`（すべて HTTPS）に限定**しています。EXE を取得して
そのまま実行する処理のため、想定外のホストが混入しても取得自体を行いません。

**通信先は `settings.json` に書かれており、利用者が確認・変更できます。**
起動時に自動生成されるので、内容を見れば「どこへ通信するのか」が分かります。
Atom フィードの URL は `api_url` から自動的に組み立てます。`api_url` の
ホストが `api.github.com` でない場合（配布元を差し替えている場合など）は
Atom による確認をせず、従来どおり API だけで確認します。

```jsonc
{
  "update": {
    "check_on_startup": true,   // false にすると起動時の確認をやめ、手動のみになる
    "check_interval_hours": 0,  // 0 は起動のたびに確認。24 にすると 1 日 1 回までになる
    "api_url": "https://api.github.com/repos/Yu5rin/MyPaste/releases/latest",
    "releases_page": "https://github.com/Yu5rin/MyPaste/releases/latest",
    "asset_name": "Atai-paste.exe"
  }
}
```

`settings.json` と `update_state.json`（前回の確認時刻）は実行ファイルと同じフォルダに
置かれます。`Program Files` 配下など書き込めない場所にある場合は
`%LOCALAPPDATA%\Atai-paste` に切り替わります。

### 更新の流れ

1. 上記の順（Atom → 必要なら API）で最新の `tag_name` を取得し、現在の
   バージョンと**数値として**比較します（文字列比較では `1.0.10` < `1.0.9`
   と誤判定するため）。
2. 新しい版があれば、確認のダイアログを表示します。
3. 「はい」を選ぶと実行ファイルをダウンロードします。SHA256 が分かって
   いれば検証します（下記参照）。進捗はトレイアイコンのツールチップに
   表示されます。
4. 検証を通った（または省略した）ら実行ファイルを入れ替え、新しい版を
   起動して自分は終了します。

ダウンロードした一時ファイルは、**入れ替えの成否にかかわらず削除**します。
書き出しが途中で失敗した場合も中途半端なファイルを残しません。強制終了などで
万一残った場合に備えて、起動時に一時フォルダの古い残骸（1 時間以上前のもの）も
掃除します。削除対象は `Atai-paste-<バージョン>.exe` という名前のものだけで、
本体の実行ファイルや無関係なファイルには触れません。

### SHA256 の検証について

**「必ず SHA256 で検証する」わけではありません。** GitHub Releases API から
添付ファイルの `digest`（`sha256:...`）を取得できたときだけ、ダウンロードした
ファイルと突き合わせて検証します。

API が使えなかった場合（前述のレート制限で 403 になった場合など）は、
Atom フィードで分かった新しい版のダウンロード URL を規則から組み立てて
更新を続行しますが、この経路では **SHA256 は分からないため検証を省略**します。
その旨はログに残します。

検証を省略しても、通信自体は HTTPS（Windows 標準の WinHTTP、証明書の検証は
OS に任せる）で行っているため、**そこで防げるのは転送中の破損まで**です。
改ざんそのものへの防御ではない点にご留意ください（ダウンロード元のホストは
前述のとおり GitHub のリリース配信ホストに限定しており、また先頭 2 バイトが
`MZ` であることの最低限の妥当性検査は省略時も行います）。

### 実行中の EXE を入れ替える仕組み

実行中の EXE は Windows がロックしているため上書きできませんが、**リネームはできます**。
そこで次の順で入れ替えます。

1. 新しい実行ファイルを、同じフォルダに `Atai-paste.exe.new` としてコピーで書き出す
2. `Atai-paste.exe` → `Atai-paste.exe.old` にリネーム
3. `Atai-paste.exe.new` → `Atai-paste.exe` にリネーム
4. 新しい EXE を起動して、自分は終了
5. 次回起動時に `.old` を削除

時間のかかる「コピー」を 1 で先に済ませておき、実際の入れ替え（2→3）は
リネーム 2 回だけで行います。リネームは同一ボリューム上ならほぼ一瞬で終わるため、
実行ファイルが存在しない瞬間はごく短くなります。

**保証されること**: 3 のリネームが失敗したことを検知できた場合は 2 を巻き戻すため、
アプリのプロセスが動き続けている限り壊れた状態にはなりません。

**保証されないこと**: 電源断や強制終了など、**OS ごと落ちるケース**では巻き戻しの
コード自体が実行されないため、上記の保証は成立しません。この窓（2 と 3 の間）で
中断されると、`Atai-paste.exe` が存在せず `.old` と `.new` だけが残った状態になり得ます。
このケースに備え、**次回起動時に `.exe` が無く `.old` だけが残っていることを検知したら、
`.old` を `.exe` に戻す（復元を試みる）**ようにしています（`update::cleanup_old`）。
ただし、複製元の `.old` 自体が壊れていた場合など、これでも救えないケースは残ります。

また `Program Files` 配下など書き込めない場所では自動更新を行わず、
リリースページを開いて手動での入れ替えを案内します。

終了処理（トレイメニューの「終了」）は、更新の入れ替え中であれば完了を
（最大 60 秒まで）待ってから行います。これにより、通常の操作で入れ替えの
途中にプロセスが終了することはありません。

## ビルド

Windows（MSVC ツールチェーン推奨）で以下を実行します。

```powershell
# 開発ビルド（コンソール表示あり・常に log.txt に記録）
cargo build

# 本番ビルド（コンソール非表示・記録は設定で ON にしたときだけ・サイズ最適化）
cargo build --release
```

生成物: `target/release/Atai-paste.exe`（単体で配布可能）。

### ビルドに関する補足

- アイコン（`src/icons/*.ico`）とマニフェスト（`app.manifest`）は、`build.rs` から
  [`embed-resource`](https://crates.io/crates/embed-resource) 経由で `app.rc` を
  コンパイルし、EXE に埋め込みます。MSVC 環境では Windows SDK の `rc.exe` が使われます。
- 設定にかかわらず常に記録する本番ビルドが欲しいときは、`--features devlog` を付けます。

```powershell
cargo build --release --features devlog
```

### GitHub Actions（手動実行のみ）

`.github/workflows/` の CI / Release ワークフローは自動実行せず、**Actions タブから手動実行**する設定（`workflow_dispatch`）です。

- **CI**: 手動実行すると `clippy` + リリースビルドを行い、`Atai-paste.exe` を Artifact として保存します。
- **Release**: タグ（例 `v1.0.0`）を入力して手動実行すると、EXE をビルドし、`RELEASE_NOTES.md`（変更点）に
  ダウンロードの表（ファイル・サイズ・SHA256）と README への案内を足した本文で、タグと同じ名前の GitHub Release を作成・添付します。

> ローカルに Windows 環境がある場合は、これらを使わず `cargo build --release` で直接ビルドできます。

## 技術仕様

| 項目 | 内容 |
| --- | --- |
| 言語 | Rust（edition 2021） |
| フック | `WH_KEYBOARD_LL`（低レベルキーボードフック） |
| キー送出 | `SendInput` API |
| 設定画面 | Win32 の標準コントロール（Common Controls v6）。Per-Monitor V2 の高 DPI 対応 |
| キー割り当て | 低レベルキーボードフックで捕まえ、別スレッドで実行。キー送出・文字入力は `SendInput`（文字は `KEYEVENTF_UNICODE`）、起動は `ShellExecuteW`、書式なし貼り付けはクリップボード（`CF_UNICODETEXT`）、履歴の記録は `AddClipboardFormatListener`、履歴の保存は DPAPI（`CryptProtectData`）、履歴の一覧はオーナードローのリストボックス、最前面は `SetWindowPos(HWND_TOPMOST)` |
| 対象アプリの判定 | `GetForegroundWindow` + `GetWindowThreadProcessId` + `OpenProcess` + `QueryFullProcessImageNameW` |
| タスクトレイ | `tray-item` クレート |
| 自動起動 | スタートアップフォルダの `.lnk`（`IShellLinkW` / `IPersistFile`） |
| HTTPS 通信 | Windows 標準の **WinHTTP**（証明書の検証は OS に任せる） |
| 更新の検証 | SHA256（`sha2` クレート）。API から取得できないときは省略（上記「SHA256 の検証について」参照） |
| 動作の記録 | `log.txt`（設定で ON にしたとき・開発時）。`log` クレートのロガーを自前で実装 |

通信に WinHTTP を使っているのは、証明書ストアを自前で抱えずに済み、
C やアセンブリのビルドを伴う TLS クレート（rustls / OpenSSL 系）を避けられるためです。
システムのプロキシ設定にも自動で従います。

### スレッド構成

- **フックスレッド**: `WH_KEYBOARD_LL` を設置し、メッセージループを回します。
  低レベルフックのコールバック配信にはメッセージループが必須です。
- **メインスレッド**: タスクトレイ（`tray-item`）を保持し、メニュー操作をチャネル経由で
  受け取ってアイコン切替・自動起動切替・終了処理を行います。`tray-item` は内部で
  独自のメッセージループを持つため、メインスレッドはチャネル受信に専念できます。
- **入力モード表示スレッド**: IME 状態の監視（100ms ごと）と表示ウィンドウを受け持ち、
  独自のメッセージループを回します。キーボードフックとは別スレッドなので、
  `Ctrl+B` のリマップには影響しません。
- **キー割り当ての実行スレッド**: フックが捕まえたキー割り当ての動作を実行します。フックの中で
  時間のかかること（プログラムを開く・クリップボードを読み書きする）をすると Windows がフックを
  外してしまうことがあるため、別のスレッドで行います。
- **設定画面スレッド**: 設定画面（とキー割り当て画面）を開いている間だけ動き、独自のメッセージループを回します。
  保存した内容はチャネルでメインスレッドへ送り、メインスレッドがフック・入力モード表示・
  トレイメニューへ反映します。
- 終了時はフックスレッドと入力モード表示スレッドへ `WM_QUIT` を送ってループを抜け、
  フックの解除と表示ウィンドウの破棄を確実に行います。設定画面が開いていれば、保存せずに閉じます。

### 自分が送出したキーの除外

リマップで送る入力には `dwExtraInfo` に固有の署名を付け、フック側で
（`LLKHF_INJECTED` と併せて）自己入力を確実に無視することで、無限ループを防ぎます。

## 安全性・運用

- 常駐メモリは数 MB 程度。
- 権限昇格は不要（`asInvoker` マニフェスト）。
- 終了時にフックを解除し、リソースリークを起こしません。
- 動作の記録は既定で OFF です。ON にしても、入力した文字は記録しません。
- 他ソフトとのキー競合は仕様外です。
